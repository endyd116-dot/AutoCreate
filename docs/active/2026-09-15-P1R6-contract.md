## 0. 공통
- 응답·에러·`config.path`·tenant 스코프·KST: R1~R5 계약 §0 그대로. 운영 API 는 `requireAdmin(roles)`(§0.2 R4).
- 🔴 **돈은 정수 원** · 부가세 별도(§12.0) · 화면은 `amountKrw`·`vatKrw`·`totalKrw` 를 **각각** 그린다.
- 🔴 **`void writeAudit` 금지**(AC 신규 규율 · C 라이브 실측): 감사·알림은 **await**. 응답 지연이 문제면 «배경 함수로 넘기고 그 호출을 await» 한다 — 던지고 잊지 않는다.
- 🔴 **`require~` 가드는 부수효과를 확인하고 호출 자체를 가른다**(AC-35).
- 키 없으면 **정직한 no-op**(«준비 중이에요 · 곧 열려요» · 빨간 오류 아님).

## 1. B — 추천인 · 영수증/세금계산서 · 회사 정보 · AM↔AC 코인 이전 · 감사 잔여
### 1.1 추천인(§19)
- `auth-register` body `referralCode?` → 400 `step:"referral"`(없는 코드·자기 코드·이미 쓴 계정).
- 코드 발급: 테넌트당 1개(`tenants.referral_code` 추가형 · 8자 대문자+숫자 · 충돌 재시도) · `GET /api/referral` → `{ code, invited:[{tenantName, at, rewarded}], rewardCoins }`.
- 보상: **피추천인 첫 유료 결제 성공 시** 양쪽에 코인 grant(`ops-promotions` 의 `kind:"referral"` 값 사용 · 없으면 0 = 비활성) · **멱등 ref** `referral:{inviterTid}:{inviteeTid}` · 감사 2행.
- 🔴 남용: 같은 `card_fp`·같은 이메일 도메인 자기추천 차단 · 체험만 하고 안 낸 초대는 보상 0(«결제 성공»이 조건).
### 1.2 영수증·세금계산서(§11.4)
- `GET /api/invoice?id=` → `{ invoice, supplier }` · `supplier` = 회사 정보(§1.3) · 없으면 `supplier:null`(화면이 «준비 중» 한 줄).
- `POST /api/tax-invoice-request { invoiceId, bizNo, bizName, email }` · `GET/POST /api/tax-profile`(다음부터 자동) · `invoices[].taxInvoice{status:"none"|"requested"|"issued", requestedAt?, issuedAt?, url?}`.
### 1.3 운영센터 «회사 정보»
- `GET/POST /api/ops-company`(super_admin · 감사 high) → `{ name, ceo, bizNo, mailOrderNo, address, email, phone, updatedBy }` — `ops_settings` 의 `company` 행.
- 🔴 **영수증·약관 하단·세금계산서가 모두 이 한 출처를 읽는다**(코드에 박지 않는다).
### 1.4 AM↔AC 코인 이전(§12 · 사장님 지시)
- `lib/coin-ledger.ts` 에 **`transferIn(tid, coins, ref, source:"AM")`**(AC 쪽 grant · bucket `purchased` · 만료 승계 규칙은 §1.4b) · `POST /api/coin-transfer { coins }` → AM 에 차감 요청 → 성공하면 AC grant.
- 🔴 **멱등 ref** `transfer:AM:{amOrderNo}` · **양쪽 감사**(AC `coin_transfer_in` · AM 쪽은 AM 계약) · 실패 시 **AC 에 아무것도 남기지 않는다**(부분 성공 금지).
- 🔴 **AM 쪽 배선은 이번 범위 밖**(AM 계약 합의 필요) — AC 쪽은 «AM 응답 규약»을 `lib/am-bridge.ts` 에 두고 **키 없으면 `not_configured`**(화면 «준비 중»).
- §1.4b 만료: 이전분은 **AC 기준 +365일**(AM 잔여 만료를 승계하지 않는다 — 단순·유리한 쪽 · 계약에 명시).
### 1.5 감사 잔여
- `fix/r4-audit-await`(진행 중) 머지 후, **`void writeAudit(`·`.catch(()=>{})` 전수 목록**을 보고하고 메인 판단으로 남길 곳/고칠 곳을 가른다.

## 2. B-1 — 내보내기 · 공유 카드 · R5 잔여 2건
### 2.1 내보내기 ZIP(§19)
- `POST /api/export-start { kinds:["post","video","revenue"], from, to }` → 202 `{ ok:true, started:true }` · **배경 함수** `export-background`(15분 · 체인 규율 R5 그대로: 진행 하트비트·잠금·재개) · `GET /api/export-status` → `{ running, startedAt, finishedAt, url?, expiresAt?, bytes?, error? }`.
- 산출: R2 `autocreate/{tid}/export/{stamp}.zip` · **presigned GET 7일** · 알림 `export_ready` · 홈 «해야 할 일» 1행.
- 내용: 글 = 마크다운 + 이미지 · 영상 = mp4 + srt + 썸네일 · 수익 = CSV(KST · «(KST)» 표기) · `manifest.json`.
- 🔴 **타 테넌트 자산 0** · 🔴 용량 상한(플랜별 · 초과 시 기간을 좁히라는 사람말).
### 2.2 공유 카드(§19 · 메인 판단 2)
- `GET /api/share-card?month=YYYY-MM&handles=0|1&channels=0|1` → `{ imageUrl, expiresAt }` — **서버 렌더**(화면 canvas 합성 금지).
- 🔴 **기본 = 금액 + 기간 + 우리 브랜드. 핸들·채널 이름은 꺼짐이 기본**(켜면 시트에 «계정 이름이 함께 보여요» 한 줄). 이유: 핸들이 박히면 «이 계정은 자동화로 돌아간다»를 공개 게시하는 셈(DESIGN §16·§7.3).
- 이미지 = R2 presigned(24h) · 카드에 **수익 0원이면 만들지 않는다**(«아직 자랑할 게 없어요»).
### 2.3 R5 잔여
- **채널별 영상 상한을 서버가 말한다**: `accounts-list.channels[].video = { maxSeconds, formats:[…] }`(naver_clip 30 · youtube_shorts 60 · reels 60(90은 Phase 5)) — 🔴 화면 상수 금지. 자동 하향 시 piece `meta.video.clampedFrom`.
- **엔드카드**: `pieces-get` 에 `meta.video.endcard{ text, url? }`(payload 에 이미 있다 · 화면에 안 내려온다).
