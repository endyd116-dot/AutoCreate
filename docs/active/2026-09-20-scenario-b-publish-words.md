## 0. 한 줄
«계정이 막혀 있어요»는 **표현이 나쁜 게 아니라 «버려짐»의 증상**이었다.
서버는 «@handle 계정은 아직 로그인 전이에요…» 라는 문장을 **이미 만들어 올려보내고 있었는데**, `publish-one.ts` 가 그걸 버리고 사유당 한 마디만 썼다.
⇒ 고친 것은 **문구 하나가 아니라 전달 경로**다. 🔴 **훑은 표에서 나온 자리 3곳**(+ 내가 고치다 만든 마침표 2곳).

## 1. 🔴 병의 모양 — 한 마디가 세 표면을 먹는다

```
lib/publish/index.ts:175   error: "@handle 계정은 아직 로그인 전이에요…"   ← 또렷한 문장을 만든다
        ↓  PublishFail.error  (계약: «사람말 한 문장 — 알림·«해야 할 일» 문구로 그대로 쓴다»)
lib/publish-one.ts:163     why = HUMAN[reason]                           ← 🔴 버리고 «계정이 막혀 있어요»
        ↓                                       ↓                                ↓
   편성표 슬롯 note                     고객 알림 본문                   pieces.meta.failReason
```

**계약은 이미 옳게 적혀 있었다** — `lib/publish/contract.ts:196` 이 `error` 를 «사람말 한 문장(…**그대로 쓴다**)» 이라 해 두었고 `detail` 을 «개발용 한 줄» 로 갈라 두었다. **소비자 한 곳이 그 계약을 안 지킨 것**이다.

🔴 **써도 되는 값인지 전수로 셌다** — `lib/publish/**` 의 `ok:false` 문장 **143개 중 143개가 우리가 쓴 한국어**다(채널 원문·예외 메시지는 전부 `detail` 쪽에 있었다).
그래도 **바닥은 남겼다**: 한글이 없거나 비었으면 `HUMAN[reason]` 으로 내려앉는다 — 뒷날 누가 채널 원문을 `error` 에 흘려도 **고객 화면에 기계 말이 나가느니 뭉갠 말이 낫다.**

## 3. 🔴 메인의 물음 — «`account_blocked` 가 계정을 `suspended` 로 적나?»

**오늘은 못 적는다. 그리고 앞으로도 못 적게 형으로 막았다.**

```ts
const ACCOUNT_ERROR_OF: Partial<Record<PublishFailReason, "login_fail" | "account_blocked">>
  = { auth_failed: "login_fail", no_creds: "login_fail" };      // ← account_blocked 를 값으로 쓰는 줄이 0개
…
if (ak && p.account_id) await classifyAndApply(…, ak === "account_blocked" ? "suspended" : "login_fail", …);
                                                 ↑ 닿을 수 없는 죽은 갈래
```
표에 `account_blocked` **키가 없어서** `ak` 는 늘 `undefined` 고, 그래서 `suspended` 갈래는 **한 번도 탈 수 없었다.**
🔴 **그런데 닿게 만들기가 너무 쉬웠다** — 누가 그 표에 한 줄 더하면 그날로 «막 연결한 계정이 발행 한 번 시켰다고 정지»가 된다.
⇒ 형에서 **`account_blocked` 를 아예 뺐다**(`Partial<Record<…, "login_fail">>`). 이제 그런 줄을 쓰면 **타입 검사가 막는다** — 주석이 아니라 컴파일러가 지킨다.
**실측**으로도 확인했다: 두 번 돌렸고 계정은 **`pending_login` 그대로**였다(아래 §5).

## 4. 🔴 덤으로 나온 것 — 같은 union 이 두 파일에 있다

`lib/publish/contract.ts` 와 `lib/cron/publish-port.ts` 에 **`PublishFailReason` 이 따로 적혀 있다.**
포트 파일이 스스로 이렇게 적어 두었다: «🔴 `lib/publish/contract.ts` 의 같은 이름 union 과 **짝**이다 — 한쪽만 고치면 포트가 갈라진다.»

🔴 **그 일이 오늘 실제로 났다.** `contract.ts` 만 고쳤더니 `tsc` 가 포트에서 울었다.
이번엔 타입 검사가 잡았지만 **사유를 «빼는» 방향이면 타입 검사가 안 운다**(둘 다 유효한 union 이라서). 그래서 자에 **글자 대조 축(④)** 을 넣었다.

## 5. 실측 — 🔴 A 의 재료(778·466·1019·1977)는 손대지 않았다

라이브 슬롯 1019 는 A 가 재는 중이라 **읽기만** 했다(옛 note «계정이 막혀 있어요» 그대로 남아 있다 — A 가 다 쓰면 다시 돌리면 바뀐다).
대신 **내 시험 테넌트에 같은 상황을 만들어** 진짜 `publishOne` 을 돌렸다.

```
tenant 761 · account 467(pending_login) · slot 1021 · piece 1979
OUTCOME  reason = account_login_needed
SLOT     note  = "@scenb-firstlogin 계정은 아직 로그인 전이에요 — 한 번만 해 두면 그다음부터는 저절로 올라가요."
PIECE    failReason = 같은 문장 (account_login_needed)
NOTIFY   «…올라가요. 발행함에서 본문을 복사해…»                     ← 마침표 하나(고친 뒤)
ACCOUNT  status = pending_login      🔴 suspended 가 아니다
```
마침표는 **두 번째 테넌트(764 · account 468 · slot 1022 · piece 1980)** 로 다시 쟀다 — `notifyOnce` 가 (테넌트·종류·제목)으로 6시간 dedup 을 걸어 761 에서는 새 알림이 안 나기 때문이다.
