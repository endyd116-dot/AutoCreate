## 0. 어떻게 쟀나 — 🔴 **제품 파일을 한 글자도 안 건드렸다**

셋이 같은 저장소에서 돈다. 그래서 파일을 고쳐 가며 찌르지 않고, **하니스 사본**(scratchpad)에
읽기 함수만 갈아 끼웠다:

| 손잡이 | 하는 일 | 무엇을 드러내나 |
|---|---|---|
| `AC_HIDE=경로` | 그 파일이 **빈 파일**로 읽힌다(`existsSync` 도 false) | 그 칸이 **정말 그 파일을 읽나** |

## 3. 🔴 찾은 것 — 값이 큰 순서

### ① ④7 `avatar`(계정 사진) — **파일이 통째로 없어져도 «닫힘»** (행 80)

```js
const fixed = inFile("lib/accounts.ts", /avatar:\s*null/);
return fixed ? ["열림", "…고정 — 값이 어디서도 안 온다"] : ["닫힘", "고정값 아님"];
```

- **찔러 본 결과**: `lib/accounts.ts` 를 **통째로 가려도 «닫힘»**. 거꾸로 `avatar: null` 을 한 줄 넣으면 «열림».
- 🔴 이 칸의 «닫힘»은 «계정 사진이 된다»가 아니라 **«내가 아는 나쁜 모양을 못 찾았다»**다.
  파일 이름이 바뀌어도 · 코드가 다른 모양으로 고정값을 써도 · 파일이 지워져도 **초록**이다.
- **고칠 값 🔴 큼**. 없는 기능을 «있다»로 세면 그 숫자가 사장님께 간다.
- **범위(제안만)**: «값이 오는 길이 있나»로 뒤집기 — ⓐ 스키마에 칸이 있나 ⓑ 그 칸을 **읽어 채우는 코드**가 있나
  ⓒ **화면이 그리나**. 셋 다 보면 부정형이 아니라 긍정형이 된다.

### ③ A12 §17 P5(릴스 90초) — **같은 뜻 다른 모양을 못 본다** (행 219)

```js
inFile("lib/video/types.ts", /VideoSeconds = 15 \| 30 \| 60 \| 90/)
```

- 설명줄은 «**`VIDEO_SECONDS` 에 90 없음**»이라고 말하는데, **재는 것은 타입 별칭**이다. 말과 자가 다르다.
- **찔러 본 결과**: 타입 별칭을 그 글자 그대로 넣으면 «닫힘». 🔴 그런데 **실제로 도는 값**
  `export const VIDEO_SECONDS = [15, 30, 60, 90];` 를 넣으면 **«열림» 그대로**.
  ⇒ 90초를 **진짜로 켜도** 타입 줄의 띄어쓰기가 다르면 이 칸은 영영 빨강이다.
- **고칠 값: 중간**. 범위(제안만): 타입 글자 대신 **`VIDEO_SECONDS` 배열에 90 이 있나**로.

## 12.2 «보나»는 기계가 센다 (자기 소스를 읽는다)

```js
/* 🔴 «이 칸이 public/ 을 지목하나» — 판정에 안 쓴다. 자를 고치면 **저절로 따라온다**(사람 표가 안 낡는다). */
const _selfLines = read("scripts/verify-r8-audit64.mjs").split("\n");
const _rowStarts = _selfLines.map((l, i) => ((/^\s*\["(.+?)", \(\) =>/.test(l) || /^\s*\{ (?:n: .*?)?name: "(.+?)"/.test(l)) ? i : -1)).filter((i) => i >= 0);
const READS_SCREEN = new Map();
_rowStarts.forEach((s, k) => {
  const nm = (_selfLines[s].match(/\["(.+?)"/) || _selfLines[s].match(/name: "(.+?)"/) || [])[1] || "";
  const body = stripComments(_selfLines.slice(s, _rowStarts[k + 1] ?? _selfLines.length).join("\n"));
  if (nm) READS_SCREEN.set(nm, /"public\//.test(body) || /\bSC\b/.test(body));
});
const axisOf = (row) => { const h = SCREEN_AXIS.find(([k]) => row.includes(k)); return h ? h[1] : "미분류"; };
const readsScreenOf = (row) => { for (const [nm, v] of READS_SCREEN) if (row.includes(nm)) return v; return null; };
```

## 12.3 🔴 미분류·겹침을 **시끄럽게** (메인 ④번)

조용히 빠지는 것이 이 표의 유일한 실패 모양이다. 그래서 **세 가지를 다 소리 내게** 한다:

```js
/* 🔴 표가 칸을 못 따라가면 **큰 소리로** 말한다 — 조용히 빠지는 것이 이 표의 유일한 실패다. */
const _axisHits = new Map(SCREEN_AXIS.map(([k]) => [k, 0]));
const _unmatched = [], _doubled = [];
for (const r of results) {
  const hits = SCREEN_AXIS.filter(([k]) => r.row.includes(k));
  hits.forEach(([k]) => _axisHits.set(k, _axisHits.get(k) + 1));
  if (hits.length === 0) _unmatched.push(r.row);
  if (hits.length > 1) _doubled.push(`${r.row} → ${hits.map(([k]) => k).join(" / ")}`);
}
const _deadKeys = [..._axisHits].filter(([, n]) => n === 0).map(([k]) => k);
const _orphan = results.filter((r) => readsScreenOf(r.row) === null);
if (_unmatched.length) console.log(`🔴 화면 축 표에 **없는 칸 ${_unmatched.length}개** — 새 칸이 생겼으면 SCREEN_AXIS 에 한 줄 더해라: ${_unmatched.join(" · ")}`);
if (_doubled.length)   console.log(`🔴 화면 축 표에 **두 번 걸리는 칸 ${_doubled.length}개** — 조각이 너무 짧다: ${_doubled.join(" · ")}`);
if (_deadKeys.length)  console.log(`🔴 화면 축 표에 **아무 칸도 안 가리키는 조각 ${_deadKeys.length}개** — 칸 이름이 바뀌었다: ${_deadKeys.join(" · ")}`);
if (_orphan.length)    console.log(`🔴 «화면을 보나»를 **못 잰 칸 ${_orphan.length}개** — 칸 선언 모양이 바뀌었다(위 _rowStarts 정규식): ${_orphan.map((r) => r.row).join(" · ")}`);
```

🔴 **내가 돌려 본 결과는 셋 다 0 이다**(칸 54 · 항목 54). 셋 중 하나라도 0이 아니면 **표가 낡은 것**이다.

## 12.4 출력 한 줄 — **문구**(메인 ②번 · 사장님이 읽는다)

숫자를 내가 실제로 냈다: **20칸**.

🔴 **처음엔 18 이라고 적었다가 내가 고쳤다 — 그 과정이 이 §12 에서 제일 중요하다.**
내 첫 `_rowStarts` 정규식이 `{ n: … name: …` 만 잡고 `{ name: …`(묶음 행 `THREE`)를 **못 잡았다.**
그래서 네 칸이 `readsScreenOf() === null` 이 되어 `_blind` 필터의 `=== false` 를 **조용히 빠져나갔고**,
그중 둘(«고지 축(4행)» · «자동승인 «신뢰 계정»(1행)»)이 실제로는 해당 칸이었다 ⇒ **18 이 아니라 20**이다.
⇒ 🔴 **내가 12.6-③에 적은 «조용히 빠지는 것이 유일한 실패 모양»을 내 코드가 그대로 저질렀다.**
   그래서 12.3 에 **네 번째 경보**(`_orphan`)를 넣었다. 그게 없었으면 이 숫자는 **틀린 채로 네게 갔다.**

```js
const _blind = results.filter((r) => ["고객", "운영"].includes(axisOf(r.row)) && readsScreenOf(r.row) === false && r.state === "닫힘");
console.log(`   닫힘 가운데 ${_blind.length}칸은 «서버에 있다»까지만 보고 셌어요 — 화면에 실제로 보이는지는 이 숫자가 말해 주지 않아요.`);
console.log(`   (어느 칸인지·왜 그런지는 docs/active/2026-09-16-audit-measure-review.md §8·§12)`);
```

**왜 이 문구인가**(CLAUDE §3):
- 🔴 «**~까지만 보고 셌어요**» — 사실 한 줄. «틀렸다»도 «못 믿는다»도 아니다.
- 🔴 «**이 숫자가 말해 주지 않아요**» — **숫자의 한계**를 말한다. 사람을 탓하지 않는다.
- 🔴 **겁주는 말이 없다**(«누락»·«위험»·«확인 안 하면 ~») — §3 의 금칙 목록을 피했다.
- 🔴 «18칸이 고장났다»로 읽히면 안 된다. **§8.4 에서 잰 대로 그중 실제 구멍은 둘뿐**이었다(E6·B5 · E6 는 이미 고쳤다).
  그래서 문구에 «못 한다»가 아니라 «**안 봤다**»를 썼다.

## 12.5 🔴 «표시가 판정을 안 바꾼다»를 **값으로** 증명하는 한 줄 (메인 ③번)

표시는 `console.log` 뿐이라 `--json` 은 **한 글자도** 안 바뀌어야 한다. 넣기 전/후로 이렇게 잰다:

```
# 넣기 전
node scripts/verify-r8-audit64.mjs --json > /tmp/before.json
# (표시를 넣는다)
node scripts/verify-r8-audit64.mjs --json > /tmp/after.json
node -e "const a=require('/tmp/before.json'),b=require('/tmp/after.json');const x=a.results||a,y=b.results||b;let d=0;for(let i=0;i<Math.max(x.length,y.length);i++){const p=x[i]||{},q=y[i]||{};if(p.row!==q.row||p.state!==q.state||p.w!==q.w)d++;}const leak=JSON.stringify(y).includes('화면:');console.log(d===0&&!leak?('✅ 판정 안 바뀜 '+y.length+'줄 · 표시가 json 으로 안 샌다'):('🔴 차이 '+d+(leak?' · 표시가 json 에 샜다':'')));process.exit(d===0&&!leak?0:1)"
```

🔴 **두 가지를 같이 본다**: ①`row`·`state`·`w` 가 한 줄도 안 바뀌나 ②**표시 문구가 `--json` 으로 새지 않나**.
②가 없으면 «표시»가 슬그머니 **데이터**가 되고, 그다음 사람이 그걸 판정에 쓴다.

## 12.6 지켜야 할 것 셋 (메인 ①②③ 그대로)

1. 🔴 **판정에 절대 안 쓴다.** `state` 를 바꾸는 순간 이것은 «표시»가 아니라 **새 게이트**다(CLAUDE §9).
2. 🔴 **`SCREEN_AXIS` 는 사람이 적는다.** 자동 판단하려 들면 §8.3 의 가짜 빨강이 돌아온다.
3. 🔴 **미분류는 시끄럽게**(12.3). 새 칸이 조용히 빠지는 것이 이 표의 유일한 실패 모양이다.
