## ③ 🔴 «취소가 취소가 아니다» — **메인이 짚은 자리와 진짜 자리가 달랐다**

### 먼저 재 봤다
메인: «`cadence-check.ts:96` 이 `draft` 도 센다 ⇒ 취소해도 그날 몫을 먹는다».
🔴 **라이브가 그렇게 말하지 않았다.**

| 잰 것 | 값 |
|---|---|
| 제품 코드에 `status = 'draft'` 를 **쓰는 곳** | **0곳**(읽는 허용 목록에만 있다) |
| 라이브 `draft` 4건 중 `scheduled_for` 가 있는 것 | **0건** ⇒ 세는 질의에 **애초에 안 걸린다** |

⇒ `draft` 는 이 고장의 얼굴이 아니었다. **그런데 «취소가 취소가 아니다»는 진짜였다.**

### 진짜 뿌리 — 두 목록이 서로의 여집합이 아니었다
| 어디 | 무엇을 적어 뒀나 |
|---|---|
| `cadence-check`(**세는 쪽**) | «`failed`·`rejected`·`published` **빼고 다 센다**» |
| `slots-skip`(**놓아 주는 쪽**) | «`generating`·`draft`·`in_review`·`approved`·`scheduled` **일 때만** 버린다» |

두 목록 **사이에 낀 상태**가 라이브에 있었다 — **`awaiting_manual` 11건 · `edited` 2건.**
그 글들은 «이날은 건너뛰기»를 눌러도 **자리는 `skipped` 가 되는데 글은 그대로** 남아 그날 몫을 계속 먹었다.
🔴 **어제 고친 «같은 상태인데 문이 한쪽에만»과 같은 집안**이다(손으로 적은 허용 목록).

### 고친 모양 — 목록을 **한 벌**로
`lib/cadence-check.ts` 에 `DAY_FREED_STATUSES`(= 자리를 놓아 준 셋) 하나를 두고 **두 곳이 그것만 본다.**
놓아 주는 쪽은 그 **여집합**을 버린다. 빼는 것은 `publishing` 하나 — **지금 나가는 중**이라 되돌릴 수 없다.

### 실측 (시험 테넌트 761 · `scripts/_smoke/cancel-frees-day-smoke.mts`)
```
«awaiting_manual» 잡아 두고 건너뛰기 → 그날 몫 0 → 1 → 0   🟢 풀렸다 (글 rejected · 자리 skipped)
«edited»         잡아 두고 건너뛰기 → 그날 몫 0 → 1 → 0   🟢 풀렸다
대조군 «publishing»            → 400 «이미 나간 글은 건너뛸 수 없어요» · 글 그대로  🟢
정리: 만든 것 3쌍 지웠다 · 남은 시험 글 0개
```

## ④ 🔴 설정 시트가 고객 값을 덮어썼다 — **한 칸이 두 뜻을 겸했다**

### 무엇이 있었나
`lib/accounts.ts` 는 `dailyCap`·`minGapMin` 을 **유효값**(워밍업이 깎은 값)으로 바꿔 내보낸다. **그 자체는 옳다** —
화면이 «오늘 몇 개 남았나»를 말해야 하고 게이트 셋이 그 값을 본다.
🔴 그런데 **설정 시트가 그 값을 «고객이 정한 값»으로 알고 미리 채웠다.** 열었다 **저장만 해도** 덮어써진다.

뿌리가 **셋**이었다:
1. `dailyCapBase`(고객 값)가 **워밍업 중일 때만** 실렸다 — 화면은 «있으면 쓰고 없으면 유효값»으로 짤 수밖에 없다.
2. 🔴 `minGapMin` 은 **원래 값을 담는 칸이 아예 없었다** — 메인이 밟은 **180 → 360** 이 이것이다.
3. 🔴 `dailyCapBase` 는 **읽는 곳이 0곳**이었다 — 있으나 마나였다(그래서 아무도 못 알아챘다).

### 고친 모양 — 갈래를 나눴다
| | 이름 | 뜻 |
|---|---|---|
| 보여 줄 값 | `dailyCap` · `minGapMin` | 지금 실제로 걸리는 값(워밍업 반영) · **편집 칸에 채우지 않는다** |
| 고칠 값 | `dailyCapBase` · `minGapBase` | 고객이 정한 값 · **언제나 싣는다**(선택 아님) |

화면(`public/app/_tpl.txt`)은 **고칠 값**으로 미리 채우고, 다르면 한 줄로 알려 준다 — «지금은 새 계정이라 1개까지만 올리고 있어요».

### 실측 (`scripts/_smoke/cap-overwrite-smoke.mts` · 761 · 값은 되돌렸다)
```
워밍업 1주차에서
  보여 줄 값 dailyCap=1 · minGapMin=360
  고칠 값   dailyCapBase=2 · minGapBase=180
시트를 «열었다 저장만» → daily_cap=2 · min_gap_min=180   🟢 그대로다
  (옛 판은 1 · 360 이 **고객 값으로** 저장됐다 — 메인이 밟은 그것)
되돌림: 2 · 180 · created_at 원래대로
```

🔴 **A 영역을 두 줄 건드렸다** — `public/app/_tpl.txt` 의 미리 채우는 자리 둘. 서버만 고치면 덮어쓰기가 **그대로 난다**(반쪽 수리).
모의 사본(`public/js/mock.js`)도 같은 커밋에서 맞췄다 — 계정 9줄 전부 두 갈래를 준다.

## ⑤ `regenNote` — **내 몫(저장·전달)은 끝. 한 겹이 A 에 남았다**

### 들어와서 본 것
서버는 이미 note 를 받아 저장하고 있었고, **`meta.angle` 뒤에 몰래 붙여** 생성기로 보내고 있었다.
🔴 그 방식이 두 가지로 나빴다:
1. `angle` 은 «이 글의 관점»이라는 **다른 뜻**이다 — 요청을 관점으로 섞으면 모델이 관점을 바꾼다.
2. 🔴 **다시 만들 때마다 쌓였다** — 세 번째 재생성이면 앞의 두 요청까지 앵글에 매달려 간다.

### 고친 모양
`regenNote` 를 **제 이름으로** 넘긴다. 글·영상 **둘 다**:
- `buildPrompt({ …, regenNote })` → «🔴 다시 만드는 이유(손님 요청 · 이번 글에서 꼭 반영): …»
- `buildVideoScript({ …, regenNote })` → «[🔴 다시 만드는 이유 …]»
- `angle` 오염은 **걷어냈다**. 비면 줄이 **아예 안 실린다**(무회귀).

⚠️ **순서가 중요했다** — 앵글 오염만 걷고 프롬프트 줄을 안 넣었으면 **note 가 모델에 아예 안 닿는 회귀**였다. 같은 커밋에서 둘 다 했다.

### 실측 (`scripts/_smoke/regen-note-smoke.mts` · 🔴 **provider 무접촉** — 프롬프트를 만들기만 하고 문자열을 본다)
```
① 한 마디를 주면 그 문장이 프롬프트에 그대로 실린다
② 안 주면 그 줄이 아예 안 실린다(191자 → 248자)
③ 앵글은 «겨울 창문 관리» 그대로 — 더럽히지 않는다
대조군 system 같음 · 줄 수 5 → 6
```

### 🔴 남은 한 겹 = **A**
화면이 아직 `{ id }` 만 보낸다(`public/app/_tpl.txt:2550` · `:3167`). 손님이 적을 자리가 **없다**.
⇒ 새 자 `verify-regen-note-reaches`(5축)를 내고 **④축만 빨간 채로** 두었다. `pending-red.json` 에 A 몫으로 등록.
