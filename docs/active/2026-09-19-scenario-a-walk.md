```

                    background:"rgb(242,244,246)" border:"2px rgb(238,240,243)"  box:"22x22"
글자 줄을 누른 뒤 → {"checked":true, "opacity":"0"}      ← 켜져도 opacity 0 그대로
```

**원인**: `public/css/ac.css` 에 **`.chk` 블록이 두 번** 있다.
| 줄 | 규칙 | 뜻 |
|---|---|---|
| 257~262 | `.chk input{position:absolute;width:0;height:0;opacity:0}` + `.chk i{...}` | 네이티브 input 을 **숨기고** 형제 `<i>` 가 네모를 그리는 방식 |
| 301~306 | `.chk input{appearance:none;width:22px;height:22px;background:...;border:...}` | input **자신**이 네모가 되는 방식 |

두 블록의 특이도가 같아서 **속성별로 뒤가 이긴다** — `width`·`height`·`background`·`border` 는 301이 이겨 «네모»가 되는데,
`opacity:0` 은 **301 블록이 다시 선언하지 않아 257 것이 그대로 살아남는다.** ⇒ 22×22 네모가 **투명하게** 그려진다.
그리고 마크업에는 `<i>` 가 없다(`hasI:false`) — 257 방식이 그리려던 네모도 없다. **두 방식 사이에서 아무것도 안 보인다.**

**영향 범위 — `class="chk"` 16곳**: `register.html`(5) · `login.html`(30일 로그인 유지) · `app/settings.html` · `app/plan.html` · `app/coins.html` · `app/_tpl.txt`.
⇒ **이 앱에서 켜고 끄는 네모는 전부 안 보인다.** 라이브 CSS 도 같다(같은 파일).

## 2. 로그인 `login.html` — ✅ 잠긴다 / 🔴 **«어디서 도느냐»에 따라 안 잠긴다**

### ✅ 된 것
- 틀린 비번 1~4번 → 매번 같은 말. 뜬 문장 그대로:
  > **이메일 또는 비밀번호가 맞지 않아요.**
  («메일이 없는 건지 비번이 틀린 건지» 안 알려 준다 — 보안상 맞다.)
- **5번째** → `423`. 뜬 문장 그대로:
  > **여러 번 실패해서 15분 동안 잠겼어요. 잠시 후 다시 시도해 주세요.**
  겁주지 않고 **언제 풀리는지**를 말한다. §3 에 맞다. ✅
- DB 도 제대로 적는다 — `users.locked_until = 2026-09-18 19:06:43`(UTC) · `now()=18:51:52` · SQL 판정 `locked=true`.

### 🔴 ❌ «초록인데 고장» ② — **잠금이 «UTC 로 도는 서버에서만» 잠긴다**
내 PC(Asia/Seoul)에서 걸었더니 **6번째가 다시 그냥 401 이고, 맞는 비번으로 그대로 들어가졌다.**
```
--- 5번째 --- ← 423 «여러 번 실패해서 15분 동안 잠겼어요…»
--- 6번째 --- ← 401 «이메일 또는 비밀번호가 맞지 않아요.»      ← 잠긴 게 아니다
맞는 비번   --- ← 200 {"ok":true}  → /app/home.html 로 들어가졌다
```

**같은 순간 · 같은 계정(user 433) · 같은 라이브 DB · 프로세스 시간대만 바꿔** 같은 요청을 던졌다:
| 서버 | 맞는 비번으로 로그인 시도 |
|---|---|
| `TZ=UTC` (= Netlify 함수의 기본) | `{"ok":false,"error":"여러 번 실패해서 15분 동안 잠겼어요…","step":"locked"}` ✅ **잠긴다** |
| `TZ=Asia/Seoul` (내 PC) | `{"ok":true,"mustChangePassword":false}` 🔴 **열린다** |

**원인** — `lib/auth-service.ts:68`
```ts
if (user.locked_until && new Date(user.locked_until) > new Date()) return { ok:false, reason:"locked" };
```
`locked_until` 은 `timestamp without time zone` 이고 **UTC 로 저장**돼 있다. 그런데 postgres.js 는 이 타입을
**프로세스의 지역시로** 읽는다. 실측(`_shots/tzproof.mjs`):
```
Node 지역시 = Asia/Seoul
DB 에 적힌 글자 : 2026-09-18 18:48:08        (UTC)
드라이버가 준 Date : 2026-09-18T09:48:08.373Z   ← 9시간 과거
지금+15분 을 같은 방식으로 읽으면 → new Date(locked_until) > new Date() ⇒ false
```
⇒ **잠금 시간(15분)이 시차(9시간)보다 짧으면 판정이 언제나 «안 잠김»** 이다.
게다가 잠글 때 `failed_logins = 0` 으로 되돌리므로(73줄) **다섯 번마다 문구만 한 번 뜨고 계속 시도된다** — 늦춰지는 게 없다.

> **지금 라이브는 안전하다**(Netlify 함수는 UTC 로 돈다 — 위 표의 윗줄).
> 문제는 **그게 우연이라는 것**이다. 코드는 «UTC 로 돌아 주기»에 기대고 있고, 아무도 그렇게 적어 두지 않았다.
> §4.5b 가 금지한 자리다. 같은 모양이 `auth-service.ts:161`(다른 잠금)에도 있다.
> ⊘ **라이브에 직접 던져 보지는 못했다** — 공유 자원 호출이 막혔다. 위 표는 **같은 코드를 TZ 만 바꿔** 잰 것이다.

### 🔴 «말이 이상한 데» ② — 처음 온 손님에게 «다시 만나서 반가워요»

## 3. 비밀번호 찾기 `forgot.html` → `reset.html` — ✅ 끝까지 갔다 / 🔴 영어 오류

### ✅ 된 것
- `forgot.html` 은 **있는 메일이든 없는 메일이든 똑같이** 답한다(계정 있는지 새어 나가지 않는다). 뜬 문장 그대로:
  > **메일을 보냈어요**
  > **30분 안에 메일 속 버튼을 눌러 주세요. 안 오면 스팸함도 확인해 주세요.**
- 토큰을 **DB 에서 읽어**(`users.reset_nonce`) 링크를 손으로 만들고(`_shots/mint-reset.mts` — 리포의 `signActionToken` 을 그대로 씀) 이어 갔다.
  → `/reset.html?t=…` → 새 비번 입력 → `200 {"ok":true}` → `/login.html` 로 넘어감 → **새 비번으로 로그인 성공**(`/app/home.html`). ✅
- **1회용이 진짜 1회용이다.** 같은 링크를 다시 쓰면:
  > **이미 사용된 링크예요. 다시 요청해 주세요.**
- 두 칸이 다르면: > **비밀번호가 서로 달라요.**

### ⊘ 메일이 진짜 가는지 — 못 쟀다. **다만 이유는 알아냈다**
`audit_logs` 에 `verify_mail_failed`(가입 2건) · `reset_mail_failed`(1건)이 남았다. 서버 로그의 진짜 이유:
```
[email] resend error { statusCode: 422, name: 'validation_error',
  message: 'Invalid `to` field. Please use our testing email address instead of domains like `example.com`.' }
```
⇒ **Resend 가 `example.com` 주소를 거부한 것**이다. **키·발신 도메인은 살아 있다**(`RESEND_FROM=AutoCreate <info@tbfa.co.kr>`).
즉 «메일 기능이 고장»이 아니라 «내 시험 주소가 가짜여서 거부»다. 진짜 주소로는 아직 **아무도 안 재 봤다.**
- ⚠️ 그래도 남는 것: **발송이 실패해도 화면은 «메일을 보냈어요»라고 말한다.** 함수 주석은 이걸 **일부러** 그렇게 했다고 적어 뒀다
  (실패를 알리면 «그 메일은 가입돼 있다»가 새 나간다 — enumeration). **맞는 판단이다.** 다만 손님 입장에선
  «보냈다는데 안 온다»로 끝나고 다음 수가 없다. 〔설계 판단이 필요한 자리 — 메인〕

### 🔴 «말이 이상한 데» ③ — **손님 화면에 영어 문장이 그대로 뜬다** (제일 나쁜 것)
토큰 없이 `/reset.html` 을 열면 **화면이 정상 폼과 똑같다**(«링크가 없어요»도, 꺼진 버튼도 없다).

한 번만 눌렀는데 브라우저에서 일어난 일 **그대로**:
```
→ POST /api/auth-change-password      ← 401 {"error":"현재 비밀번호가 맞지 않아요.","step":"current"}
→ POST /api/auth-refresh
→ POST /api/auth-change-password      ← 401 (같은 이유)
↪ 이동 /login.html?next=%2Fapp%2Fsettings.html
```
> 손님이 지금 보고 있는 화면: **`/login.html`** · 큰 글씨 «**다시 만나서 반가워요**»
> «현재 비밀번호가 맞지 않아요» 가 화면에 있나: **false**

**원인** — `public/js/ui.js:17~25`. `UI.api` 는 **모든 401 을 «세션이 끊겼다»로만** 읽는다:
```js
if (res.status === 401 && !opts.noRedirect) {
  if (!opts._retried && !path.includes("auth-refresh") && ...) {
    const r = await fetch("/api/auth-refresh", …);
    if (r && r.ok) return UI.api(path, { ...opts, _retried: true });   // ← 같은 요청을 한 번 더
  }
  … location.href = "/login.html?next=" + …                             // ← 그리고 내보낸다
}
```
서버는 사람말을 제대로 보냈고(`step:"current"`), 화면 코드도 **그 말을 칸 밑에 띄우게 적혀 있다**
(`settings.html:220` `UI.fieldError(f, "current", r.error)`). **그 줄에 닿기 전에 페이지가 떠나 버린다.**
⇒ 401 이 «세션»이 아닌 함수가 하나라도 있으면 이 모양이 난다(`auth-change-password` 가 그 하나다).
로그인 화면은 `location.pathname !== login` 가드 덕에 무사하다 — **그래서 아무도 못 봤다.** 〔A 영역 · `ui.js`〕

**이 버그는 이미 한 번 잡혔다.** `lib/guards.ts:42~44` 주석 그대로:
> 🔴 [P1R7 §3.1] `closed` 추가 — 탈퇴를 신청한 집도 상태는 `readonly` 라 **종전엔 «체험이 끝났어요»가 떴다**(그 집엔 **거짓말**이고, 정작 필요한 «되돌리기»를 못 찾게 만든다). 이유를 서버에서 가른다.

`requireWritable` 도 `UI.gate`(`ui.js:39`)도 **고쳐졌다.** 그런데 **홈의 «해야 할 일»은 다른 길로 온다**:
```js
// netlify/functions/home-summary.ts:61
if (ctx.tenant.status === "readonly") todo.push({ kind:"plan", title:"체험이 끝났어요 — 요금제를 골라 주세요", … });
```
**`closed_at` 을 안 본다.** 탈퇴하면 `tenants.status='readonly'` 가 되므로(실측: `762 · status=readonly · closed_at=2026-09-18 19:25`)
**같은 거짓말이 다른 문으로 그대로 나온다.** 한 길만 고치고 다른 길은 아무도 안 봤다. 〔B 영역〕

- **남은 날이 «31일»과 «30일» 둘 다 떴다.** 탈퇴 직후 설정 토스트는 «10월 19일에 지워져요 · **31일** 남았어요», 2초 뒤 홈은 «**30일** 남았어요». `graceDays=30` 이고 KST 로 세면 정확히 30일이다 — 경계에서 올림이 한 번 더 된다.

## F. 🔴 검증은 초록이다 — 그리고 그 초록 안에 증거가 있다

```
npx tsc --noEmit                    → 0
node scripts/verify-r8-deadends.mjs → PASS 135 · FAIL 0 · WARN 0
```
그 135줄 가운데 이 줄이 있다:
```
✓ 🔴 화면이 부르나 — 🔴 당근 — 화면이 «수익이 안 붙어요»를 말해 주나(R12-6)(`noRevenueChannels`)
      화면 1곳 [public/app/revenue.html] · 그중 화면 파일 1곳
```
**«화면 1곳 = `revenue.html`»** — 자가 보는 화면이 **수익 화면 하나**다.
어제 커밋이 말한 붙인 곳은 **둘**이었다(«수익» + «**계정 연결**»). **계정 연결 쪽은 아무도 안 세고 있다.**
그래서 `accounts.html` 에서 `soon` 가지로 새는 것을(§6) **초록인 채로** 지나쳤다.

같은 모양이 하나 더 있다:
```
✓ 🔴 «이날 겹쳐요»로 단추를 잠그지 않는다(§9 …)
      잠그는 자리 0곳 (화면이 아직 `crowd` 를 안 읽는다 — 읽기 시작하면 이 줄이 지킨다)
```
이건 **자가 스스로 «지금은 빈 걸 재고 있다»고 적어 뒀다.** ⇒ **이렇게 적어 두면 «초록인데 고장»이 아니다.**
당근 줄에도 «어느 화면을 세고 있는지»가 적혀 있었다면 어제 잡혔다.
