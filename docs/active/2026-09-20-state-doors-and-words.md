> 메인이 손으로 밟은 것 하나 + A 가 넘긴 말투 하나. 둘 다 **오늘 세 번째로 되풀이된 모양**이었다.

## 1. 🔴 «확인 필요»(`awaiting_manual`) 글이 편성표 자리를 영원히 먹었다

메인 실측: `pieces-reject` → `400 {"step":"state","error":"지금 상태에서는 버릴 수 없어요."}`

**뿌리는 «손으로 적은 허용 목록»**이었다. 문마다 목록을 따로 적으니 **한 상태가 어떤 문엔 있고 어떤 문엔 없다**:

| 상태 | 발행 | 버리기 | 수정 | 다시 만들기 |
|---|---|---|---|---|
| `awaiting_manual`(라이브 17건) | ✅ (A 가 오늘 열었다) | 🔴 **없음** | 🔴 **없음** | 🔴 **없음** |
| `failed` | ✅ | ✅ | 🔴 없음 | ✅ |
| `draft`(라이브 **0건** · 쓰는 코드 **0곳**) | — | ✅ | ✅ | ✅ |

🔴 **없는 상태는 허용하고 있는 상태는 빠뜨렸다.** 그 결과 그 글은 **못 나가고 못 버려져** 자리를 먹었고,
하루 한도가 있는 손님에게는 그게 곧 «오늘 못 올린다»다(하루 몫은 `rejected` 를 안 세니 **버리면 풀린다**).

### 고친 모양 — 목록을 지우고 **규칙 하나**로
> **막는 것은 «되돌릴 수 없는 순간»뿐이다** — `published`(이미 나갔다) · `publishing`(지금 나가는 중) · `generating`(지금 만드는 중).
> 세 문(버리기·수정·다시 만들기)이 `busyReason()` **한 규칙**을 같이 쓴다.

버리기가 밖으로 새지 않는 것은 확인했다 — `PUBLISHABLE` 에 `rejected` 가 없어 **버린 글은 절대 발행되지 않는다.**
🔴 막는 자리에는 **사실 + 다음 수**를 같이 준다(옛 문구는 사실만 있고 다음 수가 없었다 · §3 반쪽):
> «이미 올라간 글이에요 — 버리는 대신 «발행함»에서 «내리기»로 거둘 수 있어요.»

### 실측 (🔴 메인이 남겨 둔 #1977 로)
```
임퍼로 778 에 들어가 화면이 부르는 그대로 POST /api/pieces-reject {id:1977}
  → {"ok":true,"status":"rejected"}                      (옛 판은 400)
글 1977  status = rejected
자리 1019 status = rejected · note = «발행이 막혀 자리만 먹어서 버려요»   ← 🔴 자리도 같이 풀린다
계정 466 오늘 잡은 자리 2 → 1                                          ← 🔴 하루 몫이 실제로 풀렸다
이미 나간 글(1978) 버리기 → 400 «이미 올라간 글이에요 — … «내리기»로 거둘 수 있어요.»
수정(awaiting_manual)      → ok:true (옛 판은 «지금 상태에서는 수정할 수 없어요»)
다시 만들기(awaiting_manual) → ok:true · published 면 «새 자리를 잡아 주세요»
```
