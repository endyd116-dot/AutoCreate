## 0. 공통

- 응답 `{ ok:true, ... }` / 실패 `jsonError(step, err)`. 모든 함수 `export const config = { path }`.
- 모든 쿼리 `tenant_id` 스코프. 요청 body 의 tenantId 불신 — `requireUser` 의 `auth.tid` 만.
- 🔴 **KST**(CLAUDE §4.5b · DESIGN §13.5): `day` 는 **KST 날짜**(SQL `AT TIME ZONE 'Asia/Seoul'`). 수집 시각·«어제까지 확정» 판정·«이번 달» 경계 모두 KST. 화면은 `UI.dateKST/timeKST/ago`.
- 🔴 **금액**: 저장은 `amount_krw`(정수 원). 외화 소스는 `currency` + `fx_rate` 를 남기고 KRW 환산값을 `amount_krw` 에 넣는다(환율 출처는 `raw.fxSource`). 화면은 `tabular-nums`.
- 🔴 **멱등**: 같은 날 여러 번 수집해도 1행 — 유니크 `(tenant,source,account,piece,day)` + UPSERT. 재수집은 덮어쓰기(늦게 확정되는 소스가 정상이다).
- 🔴 **신선도**: `freshness = "api" | "runner" | "manual"`. 화면 배지의 근거.
- 🔴 **«없음»을 «0원»으로 쓰지 않는다**(PITFALLS AC-9). 수집 실패는 **행을 만들지 않고** `revenue_sources.status='error'` + `last_error`·마지막 성공 시각을 남긴다. 파싱 실패도 0 으로 채우지 않는다.
- 🔴 **«우리 버그»와 «고객 계정 문제»를 섞지 않는다**(AC-10). `not_configured`(키 없음)·`auth`(연결 끊김)는 고객 안내, `parse`·`provider` 는 우리 쪽 신호.
- 코인 무관 — 수익 수집은 코인을 쓰지 않는다.

## 1. 수익 커넥터 (B · `lib/revenue/**` 신규)

### 1.1 공통 인터페이스 (한 벌 · 소스별 파일은 이것만 구현)
```ts
// lib/revenue/types.ts
export type RevenueRow = {
  source: string; accountId?: number; pieceId?: number;
  day: string;            // KST YYYY-MM-DD
  amountKrw: number;      // 정수 원
  currency?: string; fxRate?: number;
  raw?: unknown;
};
export type SyncFail = { ok: false; reason: "not_configured" | "auth" | "rate_limit" | "provider" | "parse"; retriable: boolean; detail?: string };
export type SyncResult = { ok: true; rows: RevenueRow[] } | SyncFail;

// lib/revenue/index.ts
export async function syncSource(tenantId: number, src: RevenueSourceRow, range: { from: string; to: string }): Promise<SyncResult>;
```
- 기본 수집 범위 = **최근 7일**(늦게 확정되는 소스를 되돌아 덮어쓴다).
- `not_configured` 는 **에러가 아니다** — 화면에 «키를 넣으면 바로 가져와요». 재시도·알림 대상 아님.

### 1.2 소스별 (5종 전부 이번 라운드 · 키 없으면 «키 꽂으면 즉시 가동»)
| source | 방식 | 자격 | piece 귀속 |
|---|---|---|---|
| `adsense` | AdSense Management API `accounts.reports.generate`(`adsense.readonly`) · 일별 × 사이트 차원 | 사용자 구글 OAuth → `revenue_sources.cred_enc` | 사이트 → 계정 매핑 · URL 차원 있으면 `posts.external_url` 로 piece 매칭 |
| `youtube` | YouTube Analytics `reports.query`(`yt-analytics-monetary.readonly`) · `estimatedRevenue` 일별 × 영상 | 채널 OAuth(업로드 토큰 재사용) | `video id → posts.channel_ref → piece` |
| `coupang` | 쿠팡 파트너스 Open API(HMAC access/secret) · 일별 실적 · **subId 차원** | 계정별 키 | `subId = "piece_{pieceId}"`([v3.3 정정] R1 실제 코드 `lib/affiliate-coupang.ts subIdFor` 가 정본 · 이미 나간 링크가 이 형식 · 파서는 `p{n}` 도 받는다) → 직결 |
| `aliexpress` | 어필리에이트 리포트 API | 앱키 | subId |
| `linkprice` | 머천트 리포트 API | 머천트 키 | subId |
| `manual` | 사용자 입력 | — | 사용자가 고르면 귀속 |
- 자격은 **AES-256-GCM(`CREDS_ENC_KEY` · 폴백 없음)** — `revenue_sources.cred_enc`. **평문 표면 0**(수익 소스는 러너에 내려보내지 않는다).
- OAuth 토큰 갱신은 R2 의 `lib/oauth-providers.ts` 를 **import 만** 한다(파일은 B2 소유 — 수정하려면 메인에 물어라).
- 🔴 각 커넥터는 **자기 API 응답 원문 일부를 `raw` 에 남긴다**(진단용). 단, 토큰·키는 절대 `raw` 에 넣지 않는다.

### 1.3 크론 스텝 `revenue.sync` (B · `lib/cron/revenue-sync.ts`)
- `cron-tick-hourly` 우산 아래 스텝. **KST 판정**: 기본 매일 **06:00 KST** 1회 · **쿠팡은 13:00 KST**(§9.1).
- 테넌트 회전·예산 배분·격리는 R2 크론 소도구(`lib/cron/base.ts`) 그대로. 한 틱에서 테넌트당 소스 N개 상한.
- 결과: `cron_tick` 1행 + 일 있은 소스별 개별 행(`source`·`rows`·`reason`).
- **연속 3회 실패** → `revenue_sources.status='error'` + **알림함**(R2 §6A)에 1건 — «구글 연결이 끊겼어요 · 다시 연결하기». 같은 소스 24시간 1건(중복 방지).
- 🔴 수동 실행은 **`POST /api/cron-run?every=hourly&secret=`**(계약 P1R2 v2.10 · PITFALLS AC-12①). `cron-tick-*` 직접 호출 금지.

### 1.4b [v3.1 · 2026-09-14 A 가 찾은 구멍 5건 반영] 🔴 채택 사항
**(1) 게이지 분모는 서버가 준다 — 화면은 분모를 갖지 않는다.**
`ad-eligibility` 응답 최상위에 `lib/ad-eligibility.ts` 상수를 그대로 싣는다.
```
thresholds: { adpost: { posts:number, visitors:number }, ypp: { subs:number, views:number } }
```
§1.5 의 «조건 수치는 상수 한 곳» 을 화면까지 관철하는 것이다. A 가 50·300 을 화면에 박으면 정책이 바뀔 때 두 곳을 고쳐야 한다.

**(2) «신청하러 가기» 주소도 서버가 준다**(운영자가 바꿀 수 있어야 한다).
```
links: { adpost:string, adsense:string, ypp:string, coupang:string, clip:string }
```
A 는 `links` 가 없으면 공개 URL 상수로 폴백해 화면이 죽지 않게 한다.

**(3) «가입 완료했어요» 1탭 경로 신설** — 위 표의 `POST /api/ad-eligibility`. `applied` = `none→pending` · `approved` = `pending→approved`. 사용자 자기 신고이므로 **감사 1행**(`ad_media_state_claimed`)을 남긴다. 다음 수집에서 실제 승인이 확인되면 서버 판정이 이긴다.

**(4) 수동 입력 매체를 4종으로 쪼갠다**(DESIGN §9.1 이 «메타·틱톡·X·스폰서» 라고 적었는데 `manual` 하나로 뭉개면 소스별 집계가 한 줄이 된다 = 설계 축소).
source enum 에 **`meta` `tiktok` `x` `sponsor`** 추가 — 전부 `freshness:"manual"`. `manual` 은 «그 외»로 남긴다.
> 최종 source 값: `adsense` `youtube` `coupang` `aliexpress` `linkprice` `adpost` `adfit` `clip` `meta` `tiktok` `x` `sponsor` `manual`

**(5) 홈이 호출 한 번으로 그려지게 `home-summary` 에 수익을 싣는다**(홈 때문에 `revenue-daily` 를 더 부르지 않는다).
```
home-summary.revenue = { todayConfirmedKrw, todayEstimatedKrw, yesterdayKrw, monthKrw }
```
기존 `today`/`month`/`lastMonthSameDay` 키는 **그대로 둔다**(호환). 화면은 새 키가 있으면 그걸 쓰고 없으면 옛 키로 떨어진다.

### 1.4d [v3.5 · B 가 화면을 읽고 찾은 구멍 3건] 🔴 채택
**(1) 키 필드는 소스마다 여러 칸이다** — 한 칸이면 서명을 못 만들어 영원히 auth 실패.
```
KEY_FIELDS = { coupang:["accessKey","secretKey"], aliexpress:["appKey","appSecret","trackingId?"], linkprice:["affiliateId","authKey"] }
```
화면은 `POST /api/revenue-sources { action:"key", source, accountId?, creds:{ 필드명:값 } }` 로 **객체**로 보낸다(«:» 연결 문자열도 서버가 받지만 정본은 객체). 빠지면 400 «키를 모두 넣어 주세요(appSecret)».
**(2) 구글 동의 진입점** — `POST /api/revenue-sources { action:"connect", source:"adsense"|"youtube", accountId? }` → `{ ok:true, url }` → 화면 `location.href=url`(R1 `accounts-oauth-start` 와 같은 모양). 돌아오면 `/app/ad-media.html?connected=adsense`. 앱 키 없으면 503 `provider_not_configured` «준비가 아직이에요»(빨간 오류 아님).
   ⚠️ §1.2 «youtube = 업로드 토큰 재사용» **정정**: R2 `youtube_shorts` 스코프는 `youtube.upload youtube.readonly` 뿐이라 수익(`yt-analytics-monetary.readonly`)은 **따로 동의**. B2 가 `oauth-providers.ts SCOPES.youtube_shorts` 에 애널리틱스 스코프를 더하면 그때부터 한 번의 동의로 둘 다(발주함 · R3-B2).
**(3) `POST /api/ad-eligibility` 의 `source` 는 4종** — `adpost|ypp|adsense|clip`(`monetize.adsenseState`·`clipState`). 응답 `accounts[]` 에 글 채널 계정의 `adsense:{ state }` 추가.
**설계 판단(B · 승인)**: 신청 조건 판정·알림은 `revenue.sync` 06:00 실행 안에서 하루 1회(스텝 표 불변 · 수익 소스 없는 집도 애드포스트 조건은 채운다) · 외화는 환율 없으면 **환산하지 않고 `not_configured`** «환율을 넣어 주세요»(`config.fxRate` 또는 env `FX_USD_KRW` · «대충 1,300» 금지).

### 1.4c [v3.1] 🔴 `revenue-daily.days[]` 의 «없는 날»과 «0원인 날»은 다르다
