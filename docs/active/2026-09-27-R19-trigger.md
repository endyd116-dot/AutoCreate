## 1. 할 것

### ① 유튜브 한도 — **B2**(`lib/publish/youtube.ts` · 네가 R17 에 연 하나뿐인 문)
- `youtubeDailyCap()` 기본값 **100**(env `YOUTUBE_DAILY_INSERT_CAP` 로 조절은 그대로).
- 🔴 **세는 단위 = 프로젝트 전체**(모든 집 합) — 집 단위(`todayUploads(tid)`)를 버린다. §4.6 «교차 누수»가 아니다 — **수만 합치고 남의 데이터는 안 낸다.** 이 예외를 주석과 자에 **이름 붙여** 적어라.
- 🔴 **세는 창 = 최근 24시간 굴림.** 공식 문서에서 **초기화 시각을 못 찾았다**(검색 요약은 «PT 자정»이라 하나 원문 인용이 없다 · ⊘). 굴림 24시간은 **초기화가 언제든 한도를 안 넘는다.** KST 달력으로 세면 PT 초기화와 어긋나 **한도를 넘을 수 있다.**
- 🔴 **센 것 = 부른 횟수**(실패 포함) — 한도는 **호출**에 걸린다. 성공만 세면 실패가 쌓인 날 넘친다.
- 찬 날의 말(§3): «오늘은 유튜브에 올릴 수 있는 수가 다 찼어요. **내일 순서대로 이어서 올릴게요**(따로 하실 건 없어요)». 🔴 **다른 고객의 수를 화면·문장에 내지 않는다**(«73/100» 금지 · §4.6).
- 편성(R18 stagger)이 유튜브 파생을 세는 자리도 **같은 문**을 쓴다(베끼지 않는다).

### ② 숏폼 60초 — **B**(계약·코인) + **A**(화면)
- 🔴 **우리 상한 60 을 한 곳에** — `VIDEO_FORMAT_MAX_SEC` graphic·talking **90 → 60**. 채널 표 `VIDEO_CHANNEL_MAX_SEC` 는 **플랫폼 사실로 둔다**(틱톡 180 · 페북 릴스 90 …) — 실제 상한은 **둘 중 작은 것**.
- `coin-table.ts` 에서 `video_90`(42) **없앤다** — 키·라벨·길이→키 변환(`~65초 넘으면 video_90`)까지.
- 🔴 **셋이 같이 움직인다**(`writing-contracts.ts` 주석이 이미 경고했다): **표 · 코인 · 심사 축(`judge.ts duration_fit`)** + `secondsBucket`(`writing-contracts.ts:548` 의 `: 90`) + 원가 추정(`cost.ts` 컷 수).
- 라이브 데이터: 🔴 **90초 0행**(pieces·원장·가격 덮어쓰기·cadence_rules·slots · 메인 실측) — **옮길 것 없다.**
- A: 화면·모의에서 90초 선택지·«90초 42코인» 제거(`public/js/mock.js`·`ui.js` 에 있다). 🔴 **값은 서버에서 받는다** — 화면이 «15·30·60»을 새로 베끼지 마라.

### ③ 쓰레드 재사용 — **B**(`lib/video/reuse.ts`)
- `VIDEO_REUSE_TARGETS` 에 `threads` 를 넣는다. 🔴 R18 에서 빠진 까닭은 레지스트리 **`axis: "text"`** 였다 — **«글 채널로 적혀 있다» ≠ «영상을 못 올린다»**(AC-178 대용물). `lib/publish/threads.ts` 에 **`media_type:"VIDEO"` 경로가 이미 있다.** 길이 표 `threads: 60`.
- ⇒ 대상 목록을 **축 이름**이 아니라 **«영상을 올릴 수 있나»**로 고른다(다음 채널이 또 빠지지 않게).
- 🔴 쓰레드는 **앱 등록(사장님 손)** 전엔 안 열린다 — **㉯(키 칸만 비우고 다 만든다)**. «키 꽂으면 즉시 가동» 넷(R17 트리거 §3)을 지켜라.
- B2: 쓰레드 파생이 **시차 편성·발행 멱등**을 타는지 확인.
