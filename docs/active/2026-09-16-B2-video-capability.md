# 우리 영상 기계가 **무엇을 낼 수 있나** — 실측 (B2 · 2026-09-16)

> 메인 발주(R9 설계 §2.2): 사장님 «영상도 **디자인·타이포그래피·모션그래픽·자막·영상 스피드·구성**을 종합적으로 벤치마킹해야 하지 않아?»
> ⇒ **레퍼런스가 배워 와도 우리가 못 내면 장식이다.** 배우기 전에 낼 수 있는 것부터 잰다.
> 🔴 **코드 수정 0 · 실호출 0 · R2 0 · 영상 0편.** 읽고 세기만 했다.

## 0. 먼저 — 우리 영상은 **어떻게** 만들어지나(이걸 알아야 표가 읽힌다)

```
장면(그림/클립)  ──┐
자막 HTML → 브라우저로 PNG 한 장씩 캡처 ──┤ ffmpeg
나레이션(TTS) ──┘   scale/crop → (kenburns) → concat → overlay(PNG) → amix → loudnorm → mp4
```

🔴 **자막은 ffmpeg `drawtext`·`subtitles` 가 아니다 — 브라우저가 HTML/CSS 로 그린 PNG 다**(`render-video.mjs:157` `buildOverlayHtml`).
이게 이 표의 절반을 설명한다: **CSS 로 되는 것은 원리상 다 되고**(굵기·그림자·색·외곽선·자간), 지금은 **그 CSS 가 상수로 박혀 있을 뿐**이다.
⚠️ 반대로 **모션은 원리상 막혀 있다** — 구절 하나당 **PNG 한 장**을 찍어 그 구간 내내 얹는다. 코드 주석이 그 이유를 적어 뒤 뒀다:
«시간 위에서 찍지 않으므로 «애니메이션 도중» 프레임이 없다»(`render-video.mjs:189`). **정지 이미지라서 안 움직이는 게 아니라, 한 장만 찍어서 안 움직인다.**

## 2. 🔴 이 측정에서 **제일 큰 것** — 레퍼런스가 이미 배워 오는데 **아무도 안 읽는다**

`lib/video/reference.ts` 는 유튜브 URL 을 분석해 `TemplateStyle` 을 저장한다. 칸이 이미 이렇게 있다:

| 저장하는 칸 | 읽는 곳 |
|---|---|
| `structure`(서사 단계) | ✅ `director.ts:533` — **이것만 읽는다** |
| `style`(그림 스타일) | ❌ **0곳** |
| `color`(팔레트) | ❌ **0곳** |
| `caption`(자막 문법) | ❌ **0곳** |
| `pace`(컷 속도 · «cut every 5s») | ❌ **0곳** |
| `camera`(카메라 문법) | ❌ **0곳** |

확인법: `grep -rn "visualGrammar\|visual_grammar" lib/ runner/ netlify/` → `reference.ts` **자기 파일 말고 0건**.
`director.ts:533` 은 `tpl.structure` **하나만** 꺼낸다.

⇒ 🔴 **«벤치마크»의 절반은 이미 만들어져 있고, 나머지 절반(읽는 쪽)이 통째로 없다.**
그리고 그 다섯 칸 중 **`caption`·`pace` 는 위 표대로 지금 «넣을 칸» 자체가 없다**(자막 줄 수 규칙 없음 · 컷 길이 직접 지정 불가).
**배워도 못 쓰고, 쓸 데가 있어도 안 읽는다.** 이게 이 측정의 한 줄 답이다.

## 4. 못 잰 것 (정직)

- **실제로 구운 영상으로 재지 않았다** — 실호출·렌더 0 지시라 **코드만 읽었다.** 위 값은 «코드가 그렇게 시킨다»이지 «화면에서 그렇게 보였다»가 아니다.
  ⚠️ 특히 **켄번즈가 눈에 띄는 정도**(0.0012/프레임 · 최대 1.12배)는 숫자만으로는 «느낌»을 모른다 — 영상 1편을 구울 수 있게 되면 그때 본다.
- **맥·리눅스 렌더 차이**를 못 쟀다(글꼴 폴백이 갈린다 — Pretendard 가 없으면 자간·줄수가 달라진다).
- **모션그래픽 «있는 척»이 더 없는지** 전수로 훑지는 않았다 — 위 여섯 축 밖은 안 봤다.
