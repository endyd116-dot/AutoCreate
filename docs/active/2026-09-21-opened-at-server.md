# `openedAt` 서버 몫 — 손님이 적은 날이 사라지던 자리 (2026-09-21 늦게 · B)

> 브랜치 `fix/opened-at-server-b`(= `fix/cadence-and-caps-2026-09-21` 위) · **push 안 함** · DDL 안 썼다

## 1. C 가 물어 온 것
> «A 가 화면에 «언제부터 쓰셨어요» 칸을 넣어 `accounts-update` 로 `openedAt` 을 **보내기 시작**했는데 서버가 안 받는다.
> 응답에도 안 실린다 ⇒ 손님이 적은 날짜가 **저장도 안 되고 다시 열면 비어 있다.**»

🔴 **내 워크트리의 `main` 에는 A 의 화면이 아직 없다**(직접 확인했다). 그래서 «A 가 보내기 시작했다»는 **C 의 보고를 받은 것이지 내가 본 것이 아니다**(AC-9).
그와 무관하게 **서버 몫은 내 것**이고, 어제부터 `pending-red` 에 «A(화면) + B(API)»로 올라가 있던 그 항목이다. 지금 잡았다.

## 2. 고친 것 — **쓰는 길과 읽는 길을 같은 커밋에**
이 파일(`netlify/functions/accounts.ts`)이 스스로 적어 둔 규율 그대로다:
> «🔴 **허용 목록에 넣는 것까지가 «값을 만든 것»이다** — 2026-09-16 까지 네 곳에서 «저장은 200 인데 새로고침하면 사라졌다»»

| 겹 | 한 일 |
|---|---|
| 받기 | `POST /api/accounts-update { …, openedAt }` — `YYYY-MM-DD` · `null`·`""` = **모름으로 되돌리기** |
| 재기 | 모양(`YYYY-MM-DD`) · 앞날 금지(KST 오늘 기준) · 2000년 이전 금지. 🔴 **거절하면 아무것도 안 쓴다** |
| 쓰기 | `opened_at = ${raw || null}` |
| 읽기 | `AccountRow.openedAt` 으로 **응답에 싣는다**(열 자만 — 칸이 `date` 라 시각이 붙으면 «어느 날인가»가 갈린다 · §4.5b) |

🔴 «모른다»를 **아무 날짜로 바꾸지 않는다**(AC-92) — 비면 `null` 이고 워밍업은 다시 `created_at` 을 본다.
말투는 §3 — «아직 오지 않은 날이에요. 계정을 만든 날을 골라 주세요.» · «날짜는 2024-03-15 처럼 적어 주세요.»

## 3. 실측 (`scripts/_smoke/opened-at-smoke.mts` · 🔴 시험 테넌트 **761** 만 · 값은 되돌렸다)
```
① 2023-04-01 로 적으면 저장된다                       DB opened_at=2023-04-01
② 다시 열면 그대로 있다(응답에 실린다)                openedAt=2023-04-01
③ 🔴 워밍업이 그 날을 본다                            3년 된 계정이라 워밍업이 **안 걸린다**
④ «모름»으로 되돌릴 수 있다                           DB=NULL · 워밍업 **1주차로 돌아왔다**
⑤ 말이 안 되는 날은 사람말로 거절 + **아무것도 안 쓴다**
되돌림: opened_at=NULL (원래와 같다)                   PASS 7
```
③④가 한 쌍이라는 게 중요하다 — **넣으면 워밍업이 풀리고 빼면 돌아온다.** 그게 «값이 실제로 쓰인다»는 증거다.

🔴 **한 번 헛 읽었다**: 처음엔 ①이 빨갰는데 **제품이 아니라 내 자**였다 — 드라이버가 `date` 를 Date 객체로 주는 걸 문자열로 읽었다(«Sat Apr 01»). `to_char` 로 바꿔 다시 쟀다. (`_qb.mjs` 가 UTC 를 KST 로 9시간 밀어 읽던 것과 **같은 집안**이다.)

## 4. 🔴 변이 넷이 **내 수리 때문에 죽어 있었다** — 그 중 셋은 «공짜로 통과»
`verify-write-path-missing` 이 초록이 되자 변이 하니스가 **11/12**로 떨어졌다. 그런데 파 보니 **하나가 아니라 넷**이었다:

| 변이 | 왜 죽었나 |
|---|---|
| M4 | 과녁(`accounts.opened_at`)에 쓰는 길이 생겨 «여전히 울어야»가 깨졌다 — **눈에 보였다** |
| M5 · M9 · M11 | 🔴 «그 이름이 **없어야** 한다»는 **부정형 단언**이라 **과녁이 사라지면 자동으로 참** — **초록으로 남았다** |

⇒ 과녁을 **제품 밖**으로 옮겼다: 하니스가 임시 DDL 칸(`ALTER TABLE … ADD COLUMN IF NOT EXISTS <probe>`)과 읽는 줄 하나를 **만들었다 지운다.**
이제 **12/12** 이고, 제품이 어떻게 고쳐져도 안 흔들린다. → **PITFALLS AC-140**.

## 5. C 가 부탁한 한 줄 — 두 자 머리말에 넣었다
> «jsonb 안은 `pieces.meta` 말고는 **아무도 안 본다**(42칸)»

`verify-write-path-missing` 과 `verify-upstream-discarded` **양쪽 «못 하는 것»**에 적었다 — `ops_settings.features`(킬 스위치와 같은 갈래인데 jsonb 키) · `posts.stats` · `tenants.settings` · `personas.profile` 을 이름으로 들고, **왜 아직 안 만들었는지**(키가 코드마다 다르게 닿아 읽기 판정이 또 표를 못 가린다)까지 적었다.
🔴 **자를 만들지는 않았다** — C 도 «지금 만들지 말자»고 했고, 나도 DB 칸에서 같은 문제로 17칸 거짓양성을 겪었다.
