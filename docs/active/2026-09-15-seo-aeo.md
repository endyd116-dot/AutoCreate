# 글 자체의 SEO·AEO — 공식 문서로 본 «지금»과 «해야 할 것»(B3 · 2026-09-15)

> 발주: 메인(사장님 «그리고 글 자체에도 SEO AEO 가 잘 됐으면 하고 말야»).
> 규율(R8-A §1): **모든 줄에 공식 문서 URL 또는 실물**. 없으면 그 줄에 **«추정»**. 🔴 구현은 이 문서 밖(계약 = B-1 · 발행 경로 = B2).

## §0 🔴 한 줄로 — «우리 글이 검색·AI 에서 불리한 진짜 이유»(순서대로)

| 순위 | 이유 | 근거 | 구조화 데이터로 풀리나 |
|---|---|---|---|
| **1** | **검색에 들어간 글이 0편이다** — 실발행이 한 번도 없었다(`posts` 0행 · published piece 2건도 `external_url` 빈 값 · 2026-09-15 라이브 SELECT) | 전수조사 §10.1 | ❌ **아니다.** 색인될 글이 없으면 무엇을 붙여도 0이다 |
| **2** | 🔴 **없는 게 아니라 «틀린 것»이 넘어간다**(메인 지적으로 다시 보고 코드로 확인 · 아래 §1.5) — 프롬프트가 «검색어: {소재 **제목**} (월 검색 N)» 을 쓰는데, **N 은 그 제목의 값이 아니다**. 모델은 아무도 안 치는 문장을 «월 N 번 검색되는 말»로 믿고 그 문구를 노려 쓴다 | `lib/content-gen.ts:118` · `lib/topics.ts:181·233·250` | ❌ 아니다 — 이건 «무엇에 대한 글인가»의 문제다 |
| **3** | 🔴 **우리가 «머리말»을 만질 수 있는 채널이 거의 없다** — 네이버·티스토리는 **에디터로 쓴다**(러너가 브라우저로 입력). 메타 설명·JSON-LD 를 넣을 자리가 **아예 없다**. 우리가 넣을 수 있는 곳은 **워드프레스**(REST 로 `excerpt`·`slug` 가능 · 지금은 `title/content/status` 만 보낸다)와 **블로거**(API 에 `title/content/labels`)뿐 | `runner/channels/{naver-blog,tistory}.mjs` · `lib/publish/{wordpress,blogger}.ts` | 🟡 **채널 2곳에서만** |
| **4** | **내 글끼리 잇지 않는다**(내부 링크 0) — 구글이 AI 기능 문서에서 «**내부 링크를 통해 콘텐츠 접근성 확보**»를 권장하는 바로 그 항목 | [AI 기능과 내 사이트](https://developers.google.com/search/docs/appearance/ai-features?hl=ko) | ❌ 링크는 마크업이 아니다 |
| **5** | 메타 설명이 없다 — 있으면 «스니펫 품질»이 올라간다(구글이 다시 쓸 수도 있지만 권장은 유지) | [스니펫 문서](https://developers.google.com/search/docs/appearance/snippet?hl=ko) | 🟡 채널 2곳 |
| **6** | 구조화 데이터 0 | 아래 §1.2 | 🟡 **Article·Breadcrumb 만** — **FAQ·HowTo 는 이미 죽었다** |

> **한 줄**: **구조화 데이터가 없어서가 아니다.** 1) 나간 글이 없고 2) 무엇을 노리는지 정하지 않고 3) 우리가 쓰는 두 채널은 **머리말을 만질 수 없다**. 이 셋이 풀리기 전에는 JSON-LD 를 아무리 붙여도 숫자가 안 움직인다.

## §1 SEO — 공식 문서로만

### 1.1 🔴 구글이 «신호가 아니다»라고 **직접 말한 것**(업계 통설이 여기 걸린다)

출처: [구글 SEO 기본 가이드 — 집중하지 않아도 되는 것](https://developers.google.com/search/docs/fundamentals/seo-starter-guide?hl=ko)

| 통설 | 구글의 말(원문) |
|---|---|
| 메타 키워드를 넣어야 한다 | «Google 검색에서는 **키워드 메타 태그를 사용하지 않습니다**» |
| 키워드를 많이 반복하면 좋다 | 과도한 반복은 «사용자를 지치게 하며 **Google 의 스팸 정책에 위반**» |
| 도메인·URL 에 키워드가 있어야 한다 | «순위 측면에서 도메인 이름의 키워드는 **탐색경로에 표시되는 것 외에는 거의 영향을 미치지 않습니다**» |
| 🔴 **글자 수가 길어야 한다** | «**콘텐츠 길이 자체는 순위 결정과 관련 없습니다**» |
| 중복 콘텐츠는 «페널티»를 받는다 | 여러 URL 로 접근 가능해도 괜찮고 «중복 콘텐츠는 비효율적이지만 **직접 조치가 부과되지 않습니다**» |

> 🔴 **우리에게 그대로 걸리는 줄**: «글자 수 자체는 순위와 무관». R8-A 에서 우리가 **분량 손잡이**를 만들고 있는데, 그 근거를 «SEO 때문»으로 적으면 **틀린 근거**다.
> 분량을 늘릴 이유는 «실물이 그렇다 · 얇은 글은 사람이 안 읽는다»이지 «구글이 긴 글을 좋아해서»가 아니다(**B-1 에게 전달 필요**).

### 1.2 구조화 데이터 — 지금 **값이 있는 것만**

| 유형 | 지금 상태(공식) | 우리에게 |
|---|---|---|
| **FAQPage** | 🔴 **죽었다.** 2023-09-14 «공신력 있는 기존 **정부 및 보건 웹사이트에만** 표시»로 축소 → **2025-05-08 «이 기능이 Google 검색에 더 이상 표시되지 않습니다»**(지원 중단 공지) | 🔴 **메인의 기억이 맞았고 실제로는 더 나아갔다.** 우리 `faq` 블록의 **검색 값은 0**이다(독자·AEO 값은 별개 · §2) |
| **HowTo** | 🔴 **죽었다.** 2023-08 «데스크톱과 휴대기기 모두에서 더 이상 검색결과에 표시되지 않으므로 문서가 삭제» | 넣을 이유 없음 |
| **Article** | 🟢 유지 | 🟡 넣을 수 있는 채널이 워드프레스뿐(§0-3) |
| **Breadcrumb** | 🟢 유지 | 🟡 같음 |

> 출처: [FAQ 구조화 데이터](https://developers.google.com/search/docs/appearance/structured-data/faqpage?hl=ko) · [HowTo](https://developers.google.com/search/docs/appearance/structured-data/how-to?hl=ko)
> ⇒ **«구조화 데이터를 붙이자»는 결론이 2023~2025 사이에 반쯤 무너졌다.** 남은 것은 Article·Breadcrumb 둘뿐이고, 그것도 **우리가 `<head>` 를 만질 수 있는 채널에서만**.

### 1.3 메타 설명

| 물음 | 공식 문장 |
|---|---|
| 구글이 다시 쓰나 | «페이지에서 직접 가져온 콘텐츠보다 메타 설명 HTML 요소가 … **더 정확한 설명을 제공할 수 있다면 해당 요소를 사용하기도 합니다**» — 즉 **항상 쓰이지는 않는다** |
| 그럼 넣을 값이 있나 | 있다 — «우수한 메타 설명을 만들기 위한 권장사항을 따라 **페이지 스니펫의 품질을 개선하세요**» |
| 길이 | «메타 설명의 길이에는 **제한이 없지만**, Google 검색결과에서 스니펫은 **필요에 따라 잘려서** 표시됩니다» — 🔴 «155자» 같은 숫자는 **구글이 낸 적 없다**(업계 통설) |
| 네이버는 | 🟡 **공식 근거 없음** — 네이버 도메인이 우리 도구에서 fetch 차단이고, R8-A 에서 «네이버는 수치 기준을 공식으로 낸 적이 없다»가 확인됐다. **«추정»으로 둔다** |

### 1.4 내부 링크

| 물음 | 공식 문장 |
|---|---|
| 근거가 있나 | 🟢 있다 — SEO 기본 가이드: «**링크 텍스트는 사용자와 Google 에 지금 들어가려는 페이지가 어떤 페이지인지 알려줍니다**» · AI 기능 문서: «**내부 링크를 통해 콘텐츠 접근성 확보**» |
| 우리 상태 | ❌ **0** — 우리 글은 서로를 가리키지 않는다(`content-gen` 에 내부 링크 개념 없음) |

### 1.5 🔴 되짚기 — «없다»가 아니라 «틀린 것이 간다»(2026-09-15 · 메인 지적 → 코드 재확인)

내 첫 조사는 `grep keyword` 가 0 이라 «목표 검색어 축이 **없다**»로 적었다. 메인이 짚어 줘서 다시 보니 **이름이 달라서 안 잡힌 것**이었고, 실제는 더 나쁘다.

| 어디 | 코드 | 무슨 일이 나나 |
|---|---|---|
| `lib/content-gen.ts:118` | `검색어: ${a.topic.title…}${a.topic.factors.volume ? ` (월 검색 ${…})` : ""}` | 프롬프트가 **제목**을 «검색어»라고 부르고 **검색량 숫자를 붙인다** |
| `lib/topics.ts:181` `bestVolume()` | `{ volume, compIdx, keyword }` 를 고른다 | 숫자는 **씨앗 키워드 중 제일 큰 것**의 값이다 |
| `lib/topics.ts:250` | `factors.volume = bv.volume` · `bv.keyword` 는 **성장률 조회에만** 쓰고 **저장하지 않는다** | 그 숫자가 **어느 말의 값인지**가 사라진다 |

⇒ 모델이 듣는 문장: «"가을 등산 초보 준비물, 첫 산행에서…" 가 **월 3,200번** 검색된다». 실제로는 그 문장이 아니라 **«등산 준비물»** 같은 씨앗의 값이다.
⇒ 그래서 모델은 **아무도 치지 않는 문장**을 목표로 삼고, 숫자가 그 착각에 **권위**까지 준다.

🔴 **병명**: «없음»이 아니라 **대용물 판정**(AC-57 — 제목을 검색어의 대용물로 썼다) + **§8.3 재grep 교훈**(이름이 다르면 grep 0 이 «없다»의 증거가 못 된다).
🔴 **고칠 자리**: `bestVolume` 이 고른 `keyword` 를 `factors.keyword` 로 **저장**하고, 프롬프트는 **그 말**을 «검색어»로 넘긴다(없으면 «검색어 미상»으로 두고 숫자를 **빼는 쪽**이 맞다 — 숫자만 남기면 거짓이 커진다). 구현은 B-1.

## §2 AEO — «AI 가 내 글을 인용하게»

### 2.1 🔴 공식 문서가 말하는 것 — «특별한 것은 없다»

출처: [AI 기능과 내 웹사이트](https://developers.google.com/search/docs/appearance/ai-features?hl=ko)

| 물음 | 구글의 말(원문) |
|---|---|
| 특별한 마크업이 필요한가 | 🔴 **아니다** — «AI 개요 또는 AI 모드에 표시되기 위한 **추가적인 요구사항은 없으며**, 다른 특별한 최적화가 필요하지도 않습니다» · «**AI 텍스트 파일, 마크업을 따로 만들지 않아도 되며 별도로 추가해야 하는 구조화된 schema.org 데이터도 없습니다**» |
| 그럼 무엇을 하나 | 색인 가능 · robots.txt 크롤링 허용 · **내부 링크로 접근성** · 좋은 페이지 경험 · «**중요한 콘텐츠는 텍스트 형식으로 제공**» · «**구조화된 데이터가 실제로 페이지에 표시되는 텍스트와 일치**» |
| 빠지려면 | `nosnippet`·`data-nosnippet`·`max-snippet`·`noindex`·`Google-Extended` |

> 🔴 **그래서 «AEO 전용 마크업»은 없다.** 우리가 할 수 있는 것은 **글의 모양**이다(아래).

### 2.2 «한 문단이 그대로 답으로 뽑히게» — 우리 계약의 **어느 값**을 바꾸나

> 🟡 **이 절은 «추정»이다** — AI 답변에 인용된 한국 블로그 글의 실물 표본을 우리 도구로 모으지 못했다(AI 답변 화면은 로그인·동적이라 fetch 불가). 공식 문서가 «특별한 것 없다»고 말하므로, 아래는 **공식 문장에서 나오는 것만** 적는다.

| 바꿀 값 | 무엇으로 | 공식 근거 |
|---|---|---|
| **소제목 형태** | 서술형(«청소 방법») → **질문형**(«에어프라이어 기름때, 어떻게 지우나요?») | «중요한 콘텐츠는 **텍스트 형식**» + 스니펫은 질문에 답하는 조각을 고른다(스니펫 문서) |
| **첫 문장 규칙** | 소제목 바로 뒤 **첫 문장이 답**이어야 한다(배경·도입 먼저 쓰지 않는다) | 같은 곳 — 스니펫은 **문단 앞부분**에서 잘린다 |
| **문단 길이** | 답 문단은 **짧게**(2~3문장) · 그 뒤 근거·경험은 길어도 된다 | 🟡 추정(공식 수치 없음) |
| **표** | 비교·수치는 표로 — «텍스트 형식» 요구와 맞고 사람도 쉽다 | 공식 권장은 «텍스트» |
| **구조화 데이터** | **일치**가 조건이다 — 화면에 없는 내용을 마크업에만 넣으면 안 된다 | «구조화된 데이터가 실제로 표시되는 텍스트와 일치» |

### 2.3 🔴 B-1 의 «분량 손잡이»와 부딪히는가 — **부딪힌다. 다만 자리가 다르다**

| | AEO 가 원하는 것 | 분량 손잡이가 원하는 것 |
|---|---|---|
| 글 전체 | — | **길게**(실물 티스토리 8,500~12,500자) |
| **답 문단** | **짧게**(2~3문장 · 답이 먼저) | — |

> ⇒ **충돌은 «글 전체 길이»가 아니라 «문단 하나»에서 난다.** 해법은 **섞는 것**이다: 소제목마다 «짧은 답 문단 1개 + 긴 경험·근거 문단들».
> 🔴 그런데 이 모양은 **`para_repeat`·`bullet_ratio` 게이트와도 만난다** — 짧은 답 문단이 매 소제목마다 같은 말로 시작하면(«결론부터 말하면…») 곧바로 AI 티가 된다. **답 문단의 시작을 돌리는 규칙**이 같이 가야 한다.
> **판단은 메인 몫**이라고 발주에 적혀 있으므로 여기서는 «부딪히는 자리»만 못 박는다.

## §3 우리 계약과 대조(R8-A §2.2 의 4상태)

| 항목 | 상태 | 내용 |
|---|---|---|
| 제목 두 벌(`titleStyle` naver/google) | ✅ **맞다** | 채널별로 다르게 쓴다 |
| H2/H3 소제목 | ✅ | 있다 |
| 표 | ✅ | `table` 블록 |
| 이미지 `alt` | ✅ | 캡션과 분리됨(B-1) |
| **FAQ 블록** | ➖ **과하다(근거가 사라졌다)** | 🔴 구글 FAQ 리치 결과 **지원 중단**(2025-05-08). **SEO 값 0** — 남기려면 «독자에게 쓸모 있어서»라고 사유를 바꿔야 한다. R8-A 에서 B-1 이 이미 «실물은 FAQ 가 글마다 다르다»고 `optional` 로 내렸다 — **그 판단이 맞았다** |
| **목표 검색어** | 🟠 **다르다(틀린 값이 간다)** | 🔴 **값이 제일 크다**(§0-2 · §1.5) — 제목을 «검색어»라 부르고, 거기에 **다른 낱말의 검색량**을 붙여 보낸다 |
| **메타 설명** | ❌ 없다 | 🟡 넣을 수 있는 채널이 워드프레스뿐 |
| **구조화 데이터** | ❌ 없다 | Article·Breadcrumb 만 값 있음 · 채널 제약 동일 |
| **내부 링크** | ❌ 없다 | 공식 권장이 있다(§1.4) · **채널 제약 없다**(본문 안 링크라 어디서나 된다) |
| 영문 slug | 🟠 **다르다** | 계약 «문장»에만 있고 **코드가 안 보낸다**(워드프레스 REST 는 `slug` 를 받는데 `title/content/status` 만 보낸다) |

### 3.1 🔴 무엇이 값이 있고 무엇이 허례인가

| 넣을 값이 있다 | 허례다(지금은) |
|---|---|
| **목표 검색어**(글이 무엇을 노리는지) — 제목·소제목·첫 문단이 그 말을 쓰게 | **FAQPage JSON-LD** — 리치 결과가 없어졌다 |
| **내부 링크** — 어디서나 되고 공식 근거도 있다 | **HowTo JSON-LD** — 문서 자체가 삭제됐다 |
| **답 먼저 쓰기 + 질문형 소제목** — 마크업 0, 글 모양만 바꾸면 된다 | **메타 키워드** — «사용하지 않습니다»(공식) |
| **메타 설명·slug**(워드프레스) — REST 가 이미 받는다 | **글자 수 늘리기를 SEO 근거로 삼는 것** — «길이 자체는 순위와 무관»(공식) |

> 🔴 **전부 넣으면 글이 기계 같아진다**(R8-A 에서 고친 바로 그 병). 위 왼쪽 칸 **넷이면 충분**하고, 그중 **셋은 마크업이 아니라 글 모양**이다.
