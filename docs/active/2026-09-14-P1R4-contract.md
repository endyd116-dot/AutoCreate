## 1. 결제·구독·체험 (B · `lib/billing/**`·`lib/subscription.ts`·`lib/guards.ts`·`netlify/functions/billing-*.ts`)

### 1.1 코인 충전 (AM `coin-purchase.ts` 이식 · §0.1 치환 규칙)
```
POST /api/coin-purchase-start { packId }            → { ok, orderNo, mode:"oneclick"|"auth", pay?:{ url, form } , amountKrw, vatKrw, totalKrw }
GET  /api/coin-charge-return?...KICC 콜백            → 302 /app/coins.html?charged=orderNo (성공) | ?failed=사유
GET  /api/coin-history?month=                        → { ok, rows:[{ at, kind, amount, ref, expiresAt? }], balance:{ included, purchased, total } }
POST /api/coin-refund-request { orderNo }           → { ok, refundKrw, revoked, invoiceId } | { ok:false, reason:"used"|"expired"|"window" }
```
- 팩 = `lib/coin-table.ts COIN_PACKS`(₩50,000=100 · ₩100,000=220 · ₩300,000=720 · `pack_trial` ₩5,000=10 · 1회) + **DB 오버레이 `coin_price_overrides`**(운영센터 요금제 메뉴).
- «성공한 충전만 영수증 1행»(`invoices kind='coin'`).
- 환불 판정 5규칙(AM): ①미사용분만 ②회수 ≤ 잔량 ③7일 룰 우선 ④단가 = 그 주문 결제액 ÷ 받은 코인 ⑤부분 환불 없음.

### 1.2 구독
```
GET  /api/subscription                               → { ok, plan:{ key, name, priceKrw, cycle }, status, trialEndsAt?, periodEnd?, nextBillingAt?, pendingPlanKey?, cancelAtPeriodEnd, billingKey:{ has, last4?, brand? }, vatNote:"부가세 별도" }
POST /api/subscription-change { planKey, cycle }    → { ok, effectiveAt, chargeNowKrw?, pending:boolean }   // 업그레이드 = 즉시 비례 청구(prorateUpgradeSupply) · 다운 = 다음 주기
```

### 1.3 체험·readonly (§12.3)
- 가입 시 `trial_ends_at = now + currentTrialDays()`(이벤트 오버라이드 · R1 `lib/plans.ts`).
- 크론 `trial.expire`: D-3·D-1·D-0 **알림함 + 메일**(KST 09:00 · 각 1회 멱등) → 종료 시 `status='readonly'` + 홈 «해야 할 일» 행 + «30일 뒤 데이터 파기» 안내(파기 자체는 R5 · 안내만).
- `requireWritable(tid)`: `status ∈ {trial, active}` 만 통과 · `readonly`/`suspended` 는 `{ ok:false, reason:"readonly"|"suspended" }` 403 — 화면은 «요금제를 고르면 바로 이어서 돼요».
- 재가입 남용: 가입 시 이메일 + (빌키 등록 시) `card_fp` — 같은 지문으로 체험 2회째면 `trial_ends_at = now`(체험 0일 · 알림 «이미 체험을 쓰셨어요»).

### 1.4 플랜 게이트
- `checkLimit(tid, "accounts"|"runnerDevices"|"teamSeats"|"rules"|"horizonDays")` — accounts-add·runner-register·rules-save·settings 가 부른다. 초과 → `{ ok:false, reason:"plan_limit", used, limit, planKey }` 402.
- 기능형: `directorEdit`(손보기) · `autoSchedule` · `failover` · `managedRunner` · `runnerRevenue` · `teamApproval` — 해당 API 진입에서 `requireFeature`.
- 🔴 체험은 **Pro 기능 전부**(DESIGN §12.3) — `plans.trial` 행이 그 값을 가진다(시드 확인).

### 1.5 남용 방지·원가 상한 (§19 운영)
- 금칙 카테고리(성인·도박·의료 과장·타인 비방)는 R1 `findBannedWord` 게이트에 **카테고리 사전 추가**(`lib/banned-categories.ts` 상수 1곳) · 소재 단계에서 거부 + audit.
