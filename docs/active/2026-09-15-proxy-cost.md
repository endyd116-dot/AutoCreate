## 4. 🔴 «정확히»가 되려면 남은 실측 2개

이 문서의 숫자는 **공급사 공개가 + 사용량 가정**이다. 다음 두 가지가 실측되면 «정확히»가 된다.

1. ~~계정 1개가 한 달에 쓰는 트래픽(GB)~~ → **✅ 실측했다(B2 · 2026-09-15). 아래 §4.1 로 대체.**
2. **한국 IP 실구매 견적 3곳** — 공개가는 «부터»다. 계정 10개·20개·50개로 **실제 견적**(한국 재고 · sticky 보장 · 대역 상한 · 결제 조건)을 받아 표를 채운다. 실제 구매는 사장님 합동 세션 11번.

### 4.1 ✅ 트래픽 실측(B2 · 2026-09-15 · 러너 계측기 `meterContext`)

측정 방법: Playwright 컨텍스트에 CDP 를 붙여 **`Network.dataReceived`(encodedDataLength)** 를 합산했다 —
전선 위 실제 바이트다(`response.body().length` 로 세면 **압축 풀린 크기**라 3~5배 과대계상된다).
업링크는 정확한 신호가 없어 **요청 본문 길이 합**으로 근사했다(헤더·TLS 제외 — 이미지가 업링크의 거의 전부라 «몇 MB냐»는 맞는다).

| 잰 것 | 실측 | 비고 |
|---|---|---|
| 네이버 블로그 **글 1장 열기** | **↓1.24MB** (요청 133건) | `verify.post_alive` 가 하는 일 = 이 값 |
| 네이버 **글쓰기 진입**(로그인으로 튕김) | **↓3.21MB** (요청 21건) | 🔴 로그인 화면 기준 **하한** — 진짜 에디터는 이보다 무겁다 |
| 티스토리 첫 화면 | ↓2.73MB ↑117KB (요청 82건) | 참고값 |
| **생성 이미지 1장**(실제 R2 자산 24장) | **평균 0.76MB** (중앙값 0.77 · 0.65~0.87) | 업링크의 거의 전부 |
| **글 1건 이미지 6장 업로드** | **↑4.59MB** | 10장이면 ↑7.65MB |

**글 1건 합계(추정 · 실측 부품 조립)**: 에디터 진입 ↓3.2MB + 이미지 ↑4.6MB + 저장·발행 왕복 ~0.5MB ≈ **9~10MB/건**.

🔴 **가정(20~40MB)의 2~4배 과대였다.** 월 트래픽을 다시 계산하면:

| 하루 발행 | 월 건수 | 월 트래픽/계정 | GB 과금($2/GB 기준) |
|---|---|---|---|
| 1건 | 30 | **≈0.29GB** | ≈₩800 |
| 2건 | 60 | **≈0.58GB** | ≈₩1,600 |
| 3건 | 90 | **≈0.87GB** | ≈₩2,400 |

**결론(가격 결정 입력)**: 글 채널만 쓰는 계정은 트래픽이 **1GB 미만**이라 **GB 과금이 IP 과금(₩3,400~7,000)보다 싸다.**
다만 §2 표의 🟡 대로 **회전 주거용은 sticky 가 끊기면 IP 가 바뀌어** 계정-IP 1:1 이 깨진다 —
**싼 쪽이 아니라 «IP 가 안 바뀌는 쪽»을 골라야 한다**는 판단은 그대로다. GB 과금을 쓰려면 **sticky 보장**이 계약 조건이다.
⚠️ 영상(쇼츠) 계정은 이 표 밖이다 — mp4 업로드가 한 건에 수십 MB라 따로 재야 한다.

⚠️ **아직 안 잰 것**: 로그인된 **진짜 에디터**의 무게(위 3.21MB 는 로그인 화면이다). 계측기는 러너에 **상시로** 들어갔으니,
합동 세션의 첫 실발행이 돌면 그 값이 `report.bytes` 로 **자동으로** 남는다 — 그때 이 표를 확정한다.

## 5. 정직하게 말할 것(화면·안내 문구)

- IP 를 나눠도 **유튜브·인스타·쓰레드는 우리 서버에서 API 로 올라간다** — 그쪽은 IP 보다 **우리 앱·계정 신호**로 묶인다. «IP 를 나눴으니 정지가 안 된다»고 말하면 안 된다.
- 프록시가 죽으면 **그 계정은 멈춘다**(우리 IP 로 대신 나가지 않는다 · fail-closed). 이게 정지 연쇄를 막는 핵심이라 «가끔 멈출 수 있다»를 미리 알린다.
- IP 는 **빌리는 것**이다 — 공급사 사정으로 바뀔 수 있고, 바뀌면 그 계정은 새 IP 로 다시 묶인다(기록·알림).

## 6. 사장님 질문 2026-09-15: «동적 IP 로 더 싸게 안 되나 · IP 말고 다른 방법은?»

### 6.1 동적 IP(집 회선 재접속으로 IP 바꾸기) — **싸지만 이 용도엔 오히려 나쁘다**
| | 내용 |
|---|---|
| 비용 | **0원**(이미 있는 회선) |
| 되는가 | 공유기 WAN MAC 을 바꾸고 재접속하면 새 IP 를 받는 경우가 있다. 다만 한국 ISP 는 **같은 IP 를 다시 주는 일이 흔하고**, 바뀌어도 **같은 ISP·같은 대역 안**이다 — 플랫폼은 대역 단위로도 본다 |
| 🔴 치명적 1 | **계정–IP 1:1 고정이 깨진다.** 네이버·메타는 «항상 같은 곳에서 접속»을 정상으로 보고 **«매번 다른 IP 에서 로그인»을 이상 신호로 본다** — 돌릴수록 위험해질 수 있다(효과가 반대로) |
| 🔴 치명적 2 | **한 회선은 한 번에 IP 하나** — 계정 10개를 «IP 10개»로 못 만든다. 순차로 돌려야 하고 재접속마다 전체가 끊긴다 |
| 결론 | 계정 여러 개를 가르는 용도로는 **쓰지 않는다**. «계정 1~2개 + 자기 집 IP 고정»이면 애초에 프록시가 필요 없다(6.3) |

### 6.2 🟢 **모바일 회선 자체 구축 — 지금까지 중 가장 싸다**
모바일(LTE/5G)은 통신사 CGNAT 라 **IP 하나를 수천 명이 공유**한다 → 플랫폼도 «모바일 IP 공유»를 정상으로 본다. 그래서 **계정마다 IP 를 1:1 로 줄 필요가 없다** — 이게 정적 주거용과 결정적으로 다른 점이고, 원가를 한 자리 낮춘다.

| 항목 | 금액 | 메모 |
|---|---|---|
| 알뜰폰 데이터 회선(20GB급) | **정가 월 ₩19,800~24,200** · **프로모션 6~7개월 월 ₩10~900** | 2026-09 실조사 |
| 기기(4G 라우터 또는 안 쓰는 공기계 + 테더링) | 1회 **₩0~150,000** | 노트북 옆에 두면 된다(관리형 구조와 정확히 맞는다) |
| 우리 트래픽 | 계정당 월 **0.6~1.2GB 추정** → 20GB 면 **계정 10~20개** | 🔴 실측 예정(B2) |
| **계정당 월 원가** | **₩1,000 ~ 2,400**(정가 기준) · 프로모션 기간엔 거의 0 | 정적 주거용(₩5,000)의 **1/2~1/5** |
| 단점 | 회선·기기를 우리가 관리(교체·재부팅·요금제 갈아타기) · 계정 «시간차»로 써야 함 · IP 가 자주 바뀐다(모바일에선 정상) | |

⇒ **권장: 관리형은 모바일 회선 1~2개로 시작**(계정 10~20개 커버) · 특별히 중요한 계정만 정적 주거용 IP 1:1.

### 6.3 🔴 IP 보다 싸고 효과 큰 방어 6개(순서대로)
플랫폼이 보는 신호에서 IP 는 **여섯 번째쯤**이다. 아래가 앞이다.
1. **계정 워밍업** — 새 계정을 바로 쓰지 않는다. 2~4주에 걸쳐 «주 1건 → 주 2건 → 하루 1건»으로 올린다. **0원 · 효과 최대**(대량 정지의 1번 원인이 «새 계정이 첫날부터 많이 쓴다»). **우리가 자동으로 해 줄 수 있다 → R7 §2.6**
2. **발행량·간격** — 하루 1건 · 간격 랜덤 · 새벽 금지. 이미 `daily_cap`·`min_gap_min`·계정 간 30분이 있다(값을 워밍업과 연동)
3. **콘텐츠** — 중복·홍보성·링크 과다 회피. 이미 유사도·금칙어·AI티·고지 게이트가 있다
4. **계정 자체의 나이·실사용 흔적** — 오래되고 실제로 쓰던 계정일수록 안 죽는다(새로 파서 몰아 쓰는 게 제일 위험)
5. **브라우저 프로필 격리** — 이미 계정별 영구 프로필(쿠키·지문)
6. **IP 분리** — 여기서 처음 돈이 든다
7. (보험) **계정 그룹 승계** — 하나 죽어도 같은 니치의 다른 계정으로 예약이 넘어가 **수익이 안 끊긴다**(§2.5-7)
