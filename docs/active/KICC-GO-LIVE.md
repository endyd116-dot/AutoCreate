# KICC 결제 개통 문서 (KICC-GO-LIVE)

> **이 문서 하나로 끝난다.** 키를 손에 쥔 날, 위에서부터 순서대로 따라가면 된다.
> 대상: 사장님(키 등록·카드 실측) · 메인(env·재배포·스모크) · 운영자(운영센터 토글).
> 근거 코드: `lib/kicc.ts`(어댑터) · `lib/pay-route.ts`(라인 판정) · 계약 `docs/active/2026-09-14-P1R4-contract.md` §1.6.
> 마지막 갱신 2026-09-14 · 작성 B(백엔드).

---

## 0. 지금 상태 — «키만 꽂으면 된다»

| | 상태 |
|---|---|
| 코드 | **완성**(코인 충전 · 구독 청구 · 빌키 · 환불 · 이중 MID · 운영센터 토글) |
| KICC 키 | **절반 등록**(2026-09-15 메인 · 사장님 지시로 ON 에서 이식) — `KICC_MALL_ID`·`KICC_MALL_ID_KEYIN`·`KICC_API_DOMAIN`·`KICC_MODE=live` **완료** / 🔴 **`KICC_SECRET_KEY` 만 남았다** → 아직 모든 결제 경로가 «결제 준비 중이에요 · 곧 열려요»(빨간 오류 아님) |
| 고객이 보는 것 | 요금제·코인 화면은 다 보이고, 결제 버튼을 누르면 «준비 중» 안내 |
| 돈이 나가는 일 | **0건** — 키가 없으면 코드가 KICC 를 아예 부르지 않는다 |

### 0.1 🔴 Secret Key 는 «가져올» 수 없다 — 사장님이 KICC 콘솔에서 받아야 한다 (2026-09-15 실측)
| 어디서 찾아봤나 | 결과 |
|---|---|
| Netlify `hamkkework-on` env | `KICC_SECRET_KEY` 있음 · **production · is_secret=true → API·UI 어디서도 값이 `****` 로만 온다**(AC-8) |
| Netlify `tbfa-siren-cms`(MIS) env | 같음 — **마스킹** |
| 로컬 `HamkkeWorkOn/.env` · `tbfa-mis/.env` | **KICC 줄 자체가 없다**(그 프로젝트들은 Netlify env 로만 쓴다) |
⇒ Netlify 의 secret 은 **한 번 저장하면 다시 읽을 수 없다**(설계가 그렇다). 마스킹된 `****` 를 옮기면 **전 결제가 조용히 죽는다**(AC-8 이 바로 그 사고다) — 그래서 옮기지 않았다.
**사장님이 하실 일**: KICC 관리자 콘솔(또는 계약 시 받은 문서)에서 **Secret Key** 를 확인해 메인에게 준다. 분실했으면 KICC 에 **재발급** 요청(재발급하면 **함께워크ON 쪽도 같이 갈아야 한다** — 같은 키를 쓰는 중이라면).
> 참고: `KICC_MODE` 는 ON 값 그대로 **`live`** 다. Secret 이 들어오는 순간부터 **실제 카드가 결제된다** — 첫 확인은 §4 대로 **₩5,500 1건 → 전액 환불**로 한다.

우리는 **함께워크ON 사업자의 KICC 계약**을 함께 쓴다(그 사업자에 광고대행업이 등록돼 있다).
그래서 **카드 명세서에서 구별**되도록 상품명 앞에 항상 «AutoCreate »가 붙고(`AutoCreate 코인 100개 충전`), 주문번호는 `AC-` 로 시작한다.

## 1. 준비물 — KICC 에서 받아 올 것

| 받을 것 | 설명 | 없으면 |
|---|---|---|
| **가맹점 ID(MID) — 인증용** | 앱카드·ISP 결제창. 기본 라인 | 결제 자체가 안 열린다(필수) |
| **가맹점 ID(MID) — 비인증용** | 카드번호 직접 입력 · **법인카드 대응**. 함께워크ON 이 법인카드 거절을 겪고 따로 발급받은 라인 | 없어도 된다 — 인증 라인으로만 돈다(나중에 추가 가능) |
| **Secret Key** | 취소·환불 서명에 쓴다. 두 MID 공용이 원칙 | 필수 |
| (있으면) 비인증 전용 Secret Key | KICC 가 MID 별로 다른 키를 발급한 경우에만 | 없으면 공용 키를 쓴다 |
| **결제창 복귀 주소 등록** | KICC 쪽에 아래 두 주소를 «허용»으로 넣어 달라고 요청<br>`https://autocreate-endyd.netlify.app/api/coin-charge-return`<br>`https://autocreate-endyd.netlify.app/api/billing-key-return` | 결제 후 화면이 우리 사이트로 못 돌아온다 |
| **이 MID 의 허용 결제수단 코드** | 우리는 `11`(신용카드)로 요청한다. 간편결제(카카오·네이버·토스)를 같이 열려면 그 코드 목록 | 신용카드만 열린다 |

> 🔴 **키 값은 사람 손으로 Netlify 에만 넣는다.** 카톡·메일·이슈·채팅에 붙여넣지 않는다(붙여넣은 순간 그 키는 폐기 대상).

## 2. 1단계 — env 등록 (메인이 Netlify 에 넣는다)

**이름을 글자 그대로** 넣어야 한다. 이름이 하나라도 틀리면 «키 미등록»으로 간주돼 계속 «준비 중»이 뜬다.

| env 이름 | 값 | 필수 |
|---|---|---|
| `KICC_MODE` | 처음엔 `test` · 나중에 `live` | ✅ |
| `KICC_MALL_ID` | 인증용 MID | ✅ |
| `KICC_SECRET_KEY` | Secret Key | ✅ |
| `KICC_MALL_ID_KEYIN` | 비인증용 MID | ⬜(없으면 인증 라인으로 폴백) |
| `KICC_SECRET_KEY_KEYIN` | 비인증 전용 Secret Key | ⬜(키가 따로 발급됐을 때만) |
| `KICC_API_DOMAIN` | 비워 둔다 — `KICC_MODE` 에 따라 자동<br>(test `https://testpgapi.easypay.co.kr` · live `https://pgapi.easypay.co.kr`) | ⬜ |
| `KICC_PAY_METHOD_TYPE_CODE` | 비워 두면 `11`(신용카드). 간편결제까지 열 때만 `11,14,15,17` 같은 목록 | ⬜ |
| `KICC_VERIFY_MSGAUTH` | 코인 충전 콜백에서 승인 응답 서명을 검사할지. **live 전환 때 `1`** 권장 | ⬜ |
| `KICC_MSGAUTH_ENFORCE` | 평소 비워 둔다. **비상 해제용**(§7) | ⬜ |
| `SITE_URL` | `https://autocreate-endyd.netlify.app` — 결제창 복귀 주소의 근거. 이미 등록돼 있어야 한다 | ✅ |

- 등록 뒤 **재배포해야 값이 먹는다**(메인이 Netlify API 로 한다).
- 확인: `GET /api/ops-payment-settings`(운영자 로그인 · admin 이상) → `kiccConfigured: true`, `mode: "test"`.
  운영센터 «결제» 화면에도 같은 값이 뜬다(화면은 A 작업분 — 아직 안 붙었으면 이 API 로 확인).
  🔴 이 응답에도 MID·키 **값은 안 나온다**(등록됐는지 여부만). 값이 필요하면 Netlify 콘솔에서 본다.

## 3. 2단계 — test 모드 실측 3가지 (여기서 다 걸러진다)

KICC 가 준 **테스트 카드**로 한다. 테스트 테넌트(예: `smoke@test.local` 계정)로만 한다.
각 단계는 «무엇을 누르고 · 무엇이 보여야 하는가» 두 줄이다. 하나라도 어긋나면 다음 단계로 가지 않는다.

### ① 인증 결제 — 코인 충전
1. 고객 화면 → 코인 → **«첫 충전 팩»**(표시가 ₩5,000 · **청구 ₩5,500** · 부가세 별도) → «충전하기»
2. KICC 결제창이 뜬다 → 테스트 카드로 승인 → 우리 화면으로 복귀(`/app/coins.html?charged=…`)

확인:
- [ ] 코인 잔액이 **10코인** 늘었다
- [ ] 내역에 **영수증 1행**(₩5,000 + 부가세 ₩500 = ₩5,500)
- [ ] 카드사 명세서/테스트 화면의 상품명이 **«AutoCreate 코인 10개 충전»**
- [ ] DB `coin_orders.status='paid'` · `pg_mid` 에 MID 가 들어 있다(비어 있으면 안 된다)

### ② 빌키 발급 + 청구 — 구독
1. 고객 화면 → 요금제 → **«카드 등록»** → KICC 등록창 → 완료(`/app/plan.html?key=ok`)
2. 요금제에서 **Starter/Pro 선택** → 즉시 청구

확인:
- [ ] 카드 끝 4자리·카드사가 화면에 보인다
- [ ] 인보이스 1행 `paid`(공급가 / 부가세 / 청구액 3개가 따로 보인다)
- [ ] 포함 코인이 지급됐다(Pro면 150코인 · **이달 말 만료**)
- [ ] DB `billing_keys.pg_mid` 와 `invoices.pg_mid` 가 **같은 MID**
- [ ] 상품명이 «AutoCreate Pro 월 구독»

### ③ 부분 취소 — 환불
1. 운영센터 → 결제 → 그 인보이스 → **환불**(금액을 일부만 입력 · 예 ₩10,000)

확인:
- [ ] 환불 성공 · 인보이스 `refundedKrw` 가 그만큼 올라간다(전액이면 상태 `refunded`)
- [ ] 고객에게 «환불이 처리됐어요» 알림
- [ ] 코인 충전 환불이면 **미사용분만 회수**되고 이미 쓴 코인은 그대로

> 🔴 **③이 가장 중요하다.** 비인증 MID 의 Secret Key 가 실제로 다른데 같은 줄 알았다면, 그 사실은 **취소에서만** 드러난다(거래등록·승인은 서명이 없다).
> 여기서 «서명 불일치» 류 오류가 나면 KICC 에 «MID 별 Secret Key 가 같은지» 확인하고, 다르면 `KICC_SECRET_KEY_KEYIN` 한 줄만 추가하면 된다(코드 변경 없음).

## 4. 3단계 — live 전환

`KICC_MODE` 를 `test` → `live` 로 바꾸고 재배포한다. **이 한 줄로 세 가지가 동시에 바뀐다.**

1. KICC 주소가 실서버(`pgapi.easypay.co.kr`)로 바뀐다 — **진짜 돈이 나간다**
2. 승인·자동결제 응답의 **서명 검증이 «차단 모드»**가 된다(서명이 틀리면 결제를 성공으로 기록하지 않는다)
3. `KICC_VERIFY_MSGAUTH=1` 을 같이 켜면 코인 충전 콜백도 서명을 검사한다

live 첫날 절차(권장):
- [ ] 테스트 테넌트로 **첫 충전 팩 ₩5,500** 1건을 **실제 카드**로 결제
- [ ] 명세서에 «AutoCreate …»로 찍히는지 확인(구별 표시의 최종 확인은 여기서만 된다)
- [ ] 운영센터에서 **전액 환불** → 카드사 취소 확인
- [ ] 그다음에 고객에게 연다

## 5. 비인증(카드번호 직접 입력) 라인 켜기

법인카드가 인증 결제창에서 거절될 때 쓰는 라인이다. **세 가지가 모두** 참일 때만 켜진다 — 하나라도 아니면 **조용히 기존(인증) 결제**로 간다(«결제 실패»가 아니다).

1. 고객이 결제 화면에서 «카드번호 직접 입력»을 골랐다
2. 운영센터 → **결제 → «카드번호 직접 입력» 토글 ON**(권한: admin 이상)
   — 화면이 아직 없으면 `POST /api/ops-payment-settings {"keyinEnabled": true}`
3. `KICC_MALL_ID_KEYIN` 이 등록돼 있다

- 토글을 켰는데 MID 가 없으면 응답의 `effective` 가 `false` 로 온다 = **아직 안 켜진 것**. 화면도 선택지를 숨긴다.
- 어느 라인으로 결제됐는지는 운영센터 목록의 `payRoute`(인증/비인증)로 본다. MID 값 자체는 어디에도 표시하지 않는다.
- 🔴 KICC 규칙상 **승인·취소·빌키 청구/삭제는 그 거래를 만든 MID 로만** 된다. 우리는 `invoices.pg_mid`·`coin_orders.pg_mid`·`billing_keys.pg_mid` 에 그 MID 를 남겨 두고 그대로 되쓴다 — 운영자가 신경 쓸 일은 없다.

## 6. 되돌리는 법 (상황별)

| 상황 | 하는 일 | 결과 |
|---|---|---|
| 결제 전체를 급히 멈춰야 한다 | Netlify 에서 `KICC_MALL_ID` **값을 비우고** 재배포 | 모든 결제가 «결제 준비 중이에요»로 정직하게 막힌다(오류 화면 아님). 이미 등록된 카드·구독·코인은 그대로 |
| 비인증 라인만 끄고 싶다 | 운영센터 → 결제 → 토글 **OFF** | 즉시(1분 내) 인증 라인으로만 결제. 재배포 불필요 |
| live 를 다시 test 로 | `KICC_MODE=test` + 재배포 | 테스트 서버로 돌아간다. **이미 난 실결제는 되돌아가지 않는다**(환불로만 정리) |
| 서명 검증이 전건 실패한다 | `KICC_MSGAUTH_ENFORCE=off` + 재배포 | live 에서도 «경고만»으로 내려간다(결제는 통과). **임시 조치** — 원인 확인 뒤 반드시 다시 지운다 |
| 코인 콜백 서명만 끄고 싶다 | `KICC_VERIFY_MSGAUTH` 값을 비운다 | 코인 충전 콜백의 서명 검사만 꺼진다 |

## 7. 실패 신호 → 대응

| 화면·로그에 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| «결제 준비 중이에요 · 곧 열려요» | MID 또는 Secret Key 미등록(이름 오타 포함) | §2 표와 env 이름을 **글자 단위로** 대조 · 재배포했는지 확인 |
| 결제창이 아예 안 뜬다 | 복귀 주소 미등록 · 결제수단 코드 불일치 | KICC 에 복귀 주소 2개 등록 요청 · 이 MID 의 허용 코드 확인(§1) |
| 모바일에서만 실패(팝업 차단) | PC 결제창이 모바일에 뜬 것 | 코드가 이미 UA 로 분기한다 — 그래도 나면 KICC 에 기기 구분 설정 확인 |
| «카드 결제가 되지 않았어요 …» | 카드사 거절(한도·유효기간·법인카드) | 다른 카드로 재시도 · 법인카드면 §5 비인증 라인 |
| 취소만 «서명 불일치» | MID 별 Secret Key 가 다르다 | `KICC_SECRET_KEY_KEYIN` 추가(§3 ③) |
| 승인은 났는데 코인이 안 들어옴 | 콜백 서명 불일치(`msgauth_mismatch`) | 운영센터 감사 로그에서 그 주문번호 확인 → KICC 와 대조 · 필요하면 §6 비상 해제 |
| 결제 3회 실패 후 «정지» | 정상 동작(청구 실패 3회 → suspended + 자동 티켓) | 고객에게 카드 확인 안내 · 카드 교체하면 자동 재시도 |

## 8. 절대 하지 말 것

- 키 값을 **채팅·이슈·커밋·스크린샷**에 붙여넣기 (붙여넣은 키는 폐기하고 재발급)
- `.env` 파일을 git 에 커밋 (`.gitignore` 에 있지만 `-f` 로 강제하지 말 것)
- 라이브 결제로 테스트하고 **환불하지 않기**
- 운영 DB 에 손으로 인보이스·코인 행 넣기 (돈 계산은 `lib/billing-math.ts` 한 곳 · 운영센터 화면으로만)
- `drizzle-kit push` (스키마는 추가형 SQL 로만)
