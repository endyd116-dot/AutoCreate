## 🔴 «쓴 것» 칸을 **없앴다** — 다음 번호는 이렇게 센다

2026-09-26 A 가 짚었다: 이 파일에 «A — 쓴 것 **—**»라고 적혀 있는데 PITFALLS 에는 `AC-270~273` 이 **이미 있었다.**
재 보니 **다섯 칸 중 셋이 낡아 있었다**(A · B · C). 이 파일을 **직접 고친 창은 B2 하나뿐**이었다.
⇒ 🔴 **«베낀 표는 곧 거짓이 된다»**(B · 2026-09-23). «쓴 것»은 PITFALLS 가 이미 알고 있는데 **여기 한 번 더 적으니** 둘이 갈렸다.
⇒ **칸(범위)만 여기 두고, 쓴 것은 늘 진짜에서 센다:**

```bash
# 내 칸에서 이미 쓴 번호 (예: A 칸 270~279)
grep -o '^- \*\*AC-[0-9]\+' docs/rules/PITFALLS.md | grep -o '[0-9]\+' | awk '$1>=270 && $1<=279' | sort -n

# DDL 에서 이미 쓴 번호
ls drizzle/*.sql | grep -oE '[0-9]{4}' | sort -n
```
🔴 **쓰기 직전에 한 번 더 세라** — 그 사이 다른 창이 머지됐을 수 있다(`ls drizzle/ | tail -1` 로 못 막는다 · 하루에 여덟 번 겹쳤다).
