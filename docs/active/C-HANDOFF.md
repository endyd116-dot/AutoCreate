## 2. 검증 방식 정본 (이 순서를 지켜라)

### 2.1 로컬 서버 — 내 전용 포트 8901
다른 세션(메인·B·B2)이 8899를 쓴다. **절대 8899를 재사용하지 마라.**
```bash
node -e 'require("fs").rmSync(".netlify",{recursive:true,force:true})'   # 캐시 빌드 오류가 나면 반드시 먼저
(SITE_URL=http://localhost:8901 CRON_BUDGET_MS=24000 FX_USD_KRW=1400 VIDEO_PROVIDER_STUB=1 \
 npx netlify dev --port 8901 --functions-port 3998 --target-port 3997 \
 --command "node _verify/_static.mjs" --offline > /tmp/nd.log 2>&1 &)
until grep -q "Local dev server ready" /tmp/nd.log; do sleep 5; done; sleep 20
```
- `--command "node _verify/_static.mjs"` + `--target-port 3997` 로 3999 고정 충돌을 우회한다(`_verify/` 는 gitignore).
- `SITE_URL` 을 **localhost 로** 줘야 배경 함수(`generate-*-background`·`export-background`)가 내 서버로 온다.
- `CRON_BUDGET_MS`·`FX_USD_KRW`·`VIDEO_PROVIDER_STUB` 는 **로컬 전용**(프로덕션 설정 금지).
- 🔴 **AC-34: 하니스가 도는 중에 소스를 고치지 마라.** 번들이 갈려 함수가 500 이 되고, 그걸 제품 결함으로 보고할 뻔했다. 고쳤으면 **재기동 후 그 절만 다시**.

### 2.2 크론
```bash
SEC=$(grep '^CRON_SECRET=' .env | cut -d= -f2-)
curl -s -X POST "http://localhost:8901/api/cron-run?every=hourly&tid=3&secret=$SEC"
```
🔴 `?tid=` 필수 · `cron-tick-*` 직접 호출 금지(AC-12①).

### 2.3 테스트 테넌트 규칙
- 라이브 실행은 **테스트 테넌트만** · 하니스는 `ALLOWED` 집합에 든 tid 에만 DB 손질(`guard(tid)`) — 이 가드를 지우지 마라.
- **정리(cleanup)까지가 검증이다.** 돈·상태 행(`invoices·coin_orders·coin_ledger·subscriptions·tickets·runner_jobs·ai_usage`·`plan_key`)을 되돌린다.
  R4 때 남은 가짜 유료 3집이 **운영 대시보드 MRR ₩117,000 을 지어내고 있었다**(2026-09-15 사장님 승인으로 정리 · MRR ₩0).
- 🔴 **원가 방어선**: 스텁으로 돌린다고 했으면 **첫 절에서 `ai_usage` 가 전건 `model='stub'`·`cost_usd=0` 인지 확인**하고 아니면 즉시 중단(`verify-p1r5.mjs stubGuard`). 2026-09-14 에 스텁이 새서 Veo 실호출 $0.4/편이 나갔다.

### 2.4 보고 규율
- **증거 없는 «실증» 금지**: row id · 라이브 URL · 측정값 · 스샷 중 하나를 문장 옆에.
- 하니스 초록은 증거가 아니다(#9). **빨강은 4부류**(진짜 결함 / 계약 갱신 뒤처짐 / 방어 강화 뒤처짐 / **내 검사가 틀림**) — 마지막 것이 제일 흔하다.
- 로컬 인공물(AC-7 정적 폴백 · AC-12 배경 함수 동기 실행 · AC-34 실행 중 편집)을 프로덕션 결함으로 적지 마라.
- 결함은 **내가 직접 수리**(PARALLEL §2.6) · 수리하면 `PITFALLS §0` 에 AC-N 추가까지가 수리다.
- **«이 게이트를 누가 부르나» grep 을 보고에 붙여라**(AC-29).
- 🔴 **경계를 건너뛴 검사는 경계의 결함을 못 잡는다**(AC-33 의 실제 사례 — §3 «렌더» 참고).

## 4. R5·R6 에서 잡은 결함 6건 — 다시 깨지면 여기부터 본다

| # | 결함 | 왜 안 보였나 |

| 1 | **토킹 영상의 61%가 검은 화면**(still 컷 스킵 · `clipKey`·`imageKey` 둘 다 없는 장면) | 단위로는 «스킵»이 의도처럼 보였다. **payload 를 통째로 본** 검사가 잡았다 |
| 2 | 소프트 구간인데 **고객에게 «오늘 다 썼어요»** 가 갔다(영상은 만들어지고 코인도 빠진 채) | 판정 함수와 알림 함수가 한 몸이었다 — «재는 것»과 «알리는 것»을 가르는 게 수리 |
| 3 | **심사가 산출물이 아니라 계획서를 검사**했다(러너 보고가 인코딩 인자 그대로 → 일관성 검사가 항등식) | AC-31 의 13초 꼬리가 «통과»로 나온 이유. **음성 대조**(결함을 일부러 만든 보고가 떨어지는가)로만 증명된다 |
| 4 | 그 수리의 **실측값이 `reportJob` 경계에서 버려졌다** | 내 프로브가 그 경계를 **건너뛰고** 뒷단을 직접 불렀다 — 라이브 1회가 아니었으면 놓쳤다 |
| 5 | **내보내기가 한 번도 실행되지 않았다**(시작한 쪽이 잠금을 먼저 잡아 배경 함수가 자기를 거절) | 각 함수는 각자 맞다. **두 함수 사이**를 보는 검사만 잡는다 |
