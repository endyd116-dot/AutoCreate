# 영상 원가 추정에 «재시도·실패 몫»을 넣을까 — B 의견 (2026-09-21)

> 메인 물음: «추정에 **재시도 계수**를 넣을까(원가 관문이 더 보수적이 된다), 아니면 **실측이 쌓일 때까지 «못 쟀음»으로 둘까**. 어느 쪽이 덜 틀리나.»
> 지금은 **대기**다 — 이 문서는 사장님 결재 전에 판단 재료를 미리 적어 둔 것이고, **코드는 안 고쳤다.**

---

## 결론 한 줄

🔴 **둘 다 아니다. 세 번째가 덜 틀린다 — «상수로 박지 말고 우리 원장에서 재서 곱한다. 표본이 없으면 1.0 이고 «못 쟀어요»라고 적는다.»**

🔴 **그런데 재 보니 그 길이 지금은 막혀 있다.** `lib/video/providers/index.ts` 가 **성공한 호출만** `ai_usage` 에 적는다 —
**실패·폴백은 한 줄도 안 남는다**(§3). 그래서
  · 내가 제안한 «원장에서 재기»가 **지금 구조로는 불가능**하고,
  · 🔴 더 앞선 문제가 하나 있다: **`checkAiCostCap` 이 실패·폴백 호출을 못 세고 있다.**
    이건 «추정이 낮다»보다 **한 단계 아래**다 — 추정이 아니라 **실제로 쓴 것을 세는 자리**가 새는 것이다.
⇒ **순서: ①실패도 기록한다 → ②그걸로 계수를 잰다 → ③(필요하면) 상한을 내린다.** 계수는 ①없이 못 한다.

## 1. 왜 «넣는 쪽»이 원칙에 맞나 — 메인이 방금 정한 원칙이 그대로 답을 준다

메인이 클립 컷 수 내림을 승인하며 정한 규칙:

> «**추정은 실제에 맞춘다. 관문을 조이려고 추정을 부풀리지 않는다.** 관문이 조여야 하면 상한(cap)을 내리는 것이지 원가 추정을 올리는 게 아니다. 두 손잡이를 섞지 마라.»

재시도는 **부풀리기가 아니다.** 재시도하면 provider 를 **실제로 두 번 부르고 실제로 두 번 청구된다.** 그러니 재시도 몫은 **실제의 일부**다.
⇒ 클립 컷 수를 **내린** 것과 재시도 계수를 **올리는** 것은 **같은 원칙의 양면**이다. 둘 다 «실제에 맞춘다».
⇒ 「넣는다 = 관문을 조인다」가 아니다. 「넣는다 = 덜 틀린 숫자를 쓴다」이고, 관문이 조여지는 건 **결과**다.

## 2. 왜 «AM 의 1.4 를 상수로 박는 것»은 틀리나

- 🔴 **그건 우리 숫자가 아니다.** AM 원장의 재시도율(59%)·실패분(12~17%)은 **AM 의 표본**이다. 우리 표에 남의 비율을 상수로 적으면
  - 우리가 좋아져도(재시도가 줄어도) **영영 과대추정**한다 — 그리고 과대추정은 **관문이 멀쩡한 편을 막는** 쪽이라 고객이 손해를 본다.
  - 다음 사람이 **그 1.4 가 어디서 왔는지 모른다.** `video_90 = 42` 를 «B 가 잡은 임시값»이라 적어 둔 그 병을 **하나 더** 만드는 셈이다.
- ⚠️ 그리고 메인이 옮겨 준 대로 **AM 의 `costUsd` 도 제공사 청구액이 아니라 코드 상수 추정**이고 **청구서와 맞춘 적이 없다.** 남의 추정에 우리 추정을 곱하는 셈이라 오차가 곱해진다.

## 3. 🔴 그런데 우리 원장으로 재 보니 — 구멍이 하나 있다 (2026-09-21 실측 · 읽기만)

`ai_usage.ref` 가 `piece:{id}:cut{n}` 이라 **«같은 컷이 몇 번 불렸나»가 그대로 재시도 배수**다. 그래서 재 봤다.

| 잰 것 | 결과 |
|---|---|
| 같은 `(piece,cut)` 이 두 번 이상 기록된 적 | **0건** |
| piece 별 `호출 수` 대 `서로 다른 컷 수` | **모든 piece 에서 같다**(9=9 · 4=4 · 3=3 …) |
| `video_clip` 61건 중 **값(`cost_usd`>0)이 붙은 행** | **3건**(5%) |
| `tts` 85건 중 값이 붙은 행 | 5건 |
| `video_judge` 31건 중 값이 붙은 행 | 14건 |
| 편당 `video_judge` 횟수 | 대부분 1회(최대 2회) |

🔴 처음엔 **두 가지를 못 가른다**고 적었다: ⓐ 재시도가 **정말 없었다** ⓑ 재시도가 **원장에 안 남는다**.
그래서 §4-1 에 «코드 한 자리 읽으면 끝난다»고 적어 두고 **읽었다. 답은 ⓑ다.**

### 🔴 읽어서 확인한 것 — `lib/video/providers/index.ts:69~92`

```ts
while (spec && tried < 2) {
  tried++;
  const r = await callProvider(spec, inp, apiKey);
  if (!r.ok) {
    console.warn(`... 컷 ${inp.cutIdx} 실패: ...`);
    spec = inp.edit ? null : fallbackProvider(spec.key);
    continue;                    // 🔴 여기서 recordAiUsage 를 **안 부른다**
  }
  ...
  void recordAiUsage({ purpose: "video_clip", ..., ref: `piece:${id}:cut${n}` });   // 성공했을 때만
  return ...;
}
```

**`recordAiUsage` 가 성공 경로에만 있다.** ⇒ 실패한 시도는 `ai_usage` 에 **한 줄도 안 남는다.**
그래서 §3 의 «같은 `(piece,cut)` 중복 0건»은 «재시도가 없었다»가 아니라 **«구조적으로 중복이 생길 수 없다»**였다 —
성공한 컷 하나가 **서로 다른 ref 로 정확히 한 줄**을 쓰므로 중복이 나올 길이 없다. **내 §3 지표는 애초에 재시도를 못 재는 자였다.**

### 🔴 그래서 따라오는 것 셋

1. **내 제안 2번(«원장에서 재서 곱한다»)이 지금 구조로는 불가능하다.** 재려면 **실패 시도도 기록**해야 한다. 순서가 또 하나 앞당겨진다.
2. **폴백이 일어나면 provider 를 둘 불렀는데 원장엔 한 줄**이다(`fallbackProvider` 로 갈아타고 `tried < 2`). 즉 원장은 **호출 수를 확실히 적게 센다.**
3. ⚠️ 그것이 **돈을 적게 세는 것인지**는 **못 쟀다** — 실패한 호출을 제공사가 청구하는지 우리가 확인한 적이 없다.
   다만 AM 실측은 «실패분이 편당 원가의 12~17%»라고 말한다. AM 말이 맞다면 **`checkAiCostCap` 이 그만큼을 못 보고 있다**(관문이 헐겁다).
   🔴 **이건 추정 계수보다 앞선 문제다** — 계수는 «추정»을 고치는 것이고, 이건 «실제로 쓴 것을 세는 자리»가 새는 것이다.

## 4. 그래서 내 제안 — 순서

1. 🔴 **실패한 provider 호출도 원장에 남긴다**(§3 에서 «안 남는다»로 확인됐다 — 이건 이제 확인이 아니라 **할 일**이다).
   - 값은 **아는 만큼만**: 제공사가 실패를 청구하는지 모르면 `costUsd: 0` 으로 두되 **행은 남긴다**(그래야 «몇 번 불렀나»가 세어진다).
   - 🔴 **`purpose` 를 갈라라**(예: `video_clip_failed`) — 같은 `purpose` 에 섞으면 `checkAiCostCap` 의 합이 바뀌어 **관문 판정이 조용히 움직인다**. 세는 것과 무는 것을 분리한다.
   - 이게 되면 «같은 컷을 몇 번 불렀나»가 **그대로** 재시도 배수다.
2. **계수는 상수가 아니라 측정값으로 둔다.** `ai_usage` 에서 «같은 컷 재호출 배수»를 재서 곱한다.
   - 🔴 **표본이 모자라면 정확히 1.0** — 오늘과 **한 숫자도 안 다르다**(무회귀). 그리고 «못 쟀어요»라고 적는다(AC-9).
   - 표본이 쌓이면 **저절로 맞아 간다.** 우리가 좋아지면 계수도 내려간다.
3. **관문을 조여야 하면 상한(cap)을 내린다** — 추정과 섞지 않는다(메인 §1 원칙).

## 5. 🔴 사장님 가격 결재에는 **코드를 안 고쳐도 된다**

메인이 적은 계산 — «60초 ₩8,797 × 1.4 ≈ ₩12,300 ⇒ 28코인(₩14,000) 대비 ×1.1» — 은 **지금 그대로 드릴 수 있다.**
가격 판단에 필요한 건 **숫자**지 코드의 상수가 아니다. 「추정 표를 고치는 일」과 「사장님께 «AM 실측으로 보정하면 이렇게 됩니다» 한 줄을 드리는 일」은 **다른 일**이고, **뒤엣것은 오늘 할 수 있다.**
⇒ 결재를 기다리느라 추정 표를 붙들고 있을 이유가 없고, 반대로 결재를 위해 추정 표를 **급히 고칠 이유도 없다.**

> 🔴 그 한 줄을 드릴 때 **«AM 의 추정에 AM 의 재시도율을 곱한 값»**이라고 밝혀야 한다. 우리 실측이 아니다.

## 6. 못 쟀음 (정직하게)

- **추정이 실제 청구와 맞는지 못 쟀다.** 우리도 AM 도 청구서와 맞춘 적이 없다.
- **우리 재시도율을 못 쟀다** — 표본이 거의 스텁이다(§3).
- **클립 추정이 내려간 것이 관문에 얼마나 헐거운지 못 쟀다** — 클립 편 실측 0.
- `video_clip` 값 0 행 95% 가 «스텁이라서»인지 «원장에 안 붙어서»인지 **못 가렸다**(§3 스텁 경로는 `costUsd: 0` 으로 **행은 남긴다** — 그러니 스텁 쪽이 유력하지만 단정하지 않는다).
- 🔴 **실패한 provider 호출을 제공사가 청구하는지 못 쟀다.** 이게 «관문이 헐겁다»의 크기를 정하는데, 우리 청구서를 본 적이 없다.
