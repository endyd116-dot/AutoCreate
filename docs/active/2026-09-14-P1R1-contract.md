## 0. 공통
- 응답: `{ ok:true, ... }` / `{ ok:false, error:"사람말", step:"snake" }` (`lib/response.ts`). 401 → 화면은 `UI.api` 가 로그인으로 보낸다.
- 시각: 서버 저장 UTC(timestamp) · 응답은 ISO 문자열(`utcDate().toISOString()`) · 화면은 `UI.timeKST/dateKST`.
- 채널 키(`channel`): `naver_blog | tistory | blogger | wordpress | threads | instagram | youtube_shorts | naver_clip | reels | tiktok` (channel_registry.key).
- 연결 방식(계약): `naver_blog`·`tistory` = 자격 저장(session) · `wordpress` = App Password(siteUrl·loginId·appPassword → REST 인증 확인) · `blogger`·`threads`·`instagram`·`youtube_shorts`·`reels`·`tiktok` = OAuth(각 앱). **R1 에서 끝까지 동작 = session 2채널 + wordpress**. OAuth 채널은 `accounts-oauth-start` 가 env 앱 키 없으면 `{ ok:false, step:"provider_not_configured", error:"준비 중이에요" }` — 화면·API 완성, 키 꽂으면 가동(CLAUDE §8).

## 1. 계정 `accounts`
```
GET  /api/accounts-list
  → { ok:true, accounts:[{ id, channel, handle, displayName, status, healthScore, postsToday, dailyCap, lastPostAt?, personaId?, hasCreds:boolean }],
       channels:[{ key, label, category, publishVia, status, connectMethod:"session"|"app_password"|"oauth", configured:boolean }] }   // channel_registry + 연결 방식 · configured = OAuth 앱 키 존재(session/app_password 는 항상 true)
POST /api/accounts-add   body { channel, handle, loginId?, password?, siteUrl?, appPassword?, displayName? }   // session: loginId+password · wordpress: siteUrl+loginId+appPassword · 자격은 AES-256-GCM(lib/creds-crypto.ts) → account_creds(kind "password"|"app_password")
  → { ok:true, account:{ id, channel, handle, status:"pending_login" } }                     // 세션 검증은 러너 몫(R2) → 지금은 pending_login 고정
  ✗ 한도 초과 → { ok:false, step:"limit", error:"이 요금제에서는 계정을 N개까지 연결할 수 있어요." }
  ✗ 중복(tenant, channel, handle) → step:"duplicate"
POST /api/accounts-remove body { id }   → { ok:true }                                        // creds purged_at 기록(삭제 아님)
POST /api/accounts-update body { id, displayName?, dailyCap?, minGapMin?, personaId?, proxyUrl?, goldenHours?:[number], monetize?:{ coupangAccessKey?, coupangSecretKey?, adpostMediaId?, adsensePub? } }
  → { ok:true, account:{ ...AccountRow, monetize:{ coupang:boolean, adpost:boolean, adsense:boolean } } }   // 쿠팡 키는 암호화(account_creds kind "coupang") · 응답은 boolean 만
POST /api/accounts-oauth-start  body { channel } → { ok:true, url } | { ok:false, step:"provider_not_configured" }
GET  /api/accounts-oauth-return?state=&code=     → 302 /app/accounts.html?connected=<channel>
GET  /api/personas-list → { ok:true, personas:[Persona] }
POST /api/personas-save body { id?, name, profile } → { ok:true, persona:Persona }
Persona = { id, name, profile:{ region?, family?, job?, home?, brands?:[string], tone?, interests?:[string], banned?:[string], signature? } }   // DESIGN §5C.2
AccountRow 에 추가: minGapMin, goldenHours?:[number], proxyUrl?:string(마스킹), monetize:{ coupang, adpost, adsense }
```
status 어휘: `active | cooldown | limited | suspended | disconnected | pending_login` (DESIGN §7.1 그대로).

## 3. 디렉터 `director`
```
POST /api/director-propose body { topicId }
  → { ok:true, brief:Brief }
POST /api/director-confirm body { briefId, pieces?:[PieceSpecPatch] }                        // pieces 생략 = 제안 그대로
  → { ok:true, briefId, pieceIds:[number], coinsCharged:number, coinsLeft:number }
  ✗ 코인 부족 → { ok:false, step:"coin_short", error:"코인이 N개 부족해요.", need:number, have:number }
Brief = { id, topicId, goal, mode:"auto"|"reviewed", coinCost:number, coinsLeft:number, reasons:[string],
          pieces:[PieceSpec] }
PieceSpec = { key:string, channel, accountId:number|null, accountHandle:string|null, format:"story"|"info"|"listicle"|"compare"|"qna"|"guide"|"cardnews",
              emotionKey:string, composition:string, lengthHint:{ words:number }, images:{ count:number, style:"photo"|"illust"|"infographic", heroNeeded:boolean },
              monetize:{ affiliate:{ provider:"coupang", productQuery:string, slot:"mid"|"end"|"both" }|null, adDisclosure:boolean },
              schedule:{ at:string(ISO), slotReason:string }, coinCost:number }   // DESIGN §5.2 전 필드
Brief.goal = "adsense"|"adpost"|"affiliate"|"ypp"|"clip_incentive"|"mixed"
PieceSpecPatch = { key, accountId?, format?, emotionKey?, images?:{ count?, style? }, monetize?:{ affiliate?:{ productQuery, slot }|null }, schedule?:{ at }, drop?:true }
```
- 확정 시 B 가 하는 일: piece 행(status `generating`) + slot 행(`origin:"manual"`, status `producing`) 생성 → 코인 `consume`(ref = `piece:{id}` 멱등) → 백그라운드 생성 함수 호출.

## 5. 편성 규칙 `rules` · 슬롯 `slots`
```
GET  /api/rules-list                     → { ok:true, rules:[Rule], settings:{ autoSchedule:boolean, produceLeadDays:number, reviewPolicy:"silence_approves"|"require_confirm", horizonDays:number }, coinsPerWeek:number }
POST /api/rules-save    body { rules:[RuleInput] }  → { ok:true, rules:[Rule], coinsPerWeek:number, slotsCreated:number }   // 전체 교체(멱등) · 저장 직후 slots.roll 1회
POST /api/rules-settings body { autoSchedule?, produceLeadDays?, reviewPolicy?, horizonDays? } → { ok:true, settings }
GET  /api/slots-list?from=YYYY-MM-DD&to=YYYY-MM-DD → { ok:true, slots:[Slot] }
POST /api/slots-skip    body { id }      → { ok:true }
Rule = { id, channel, kind:"post", accountMode:"auto"|"fixed", accountId?, every:"week"|"day", count:number, weekdays?:[0-6], preferredHour?:number, formatHint?, active:boolean }
RuleInput = Rule without id (id 있으면 갱신)
Slot = { id, date:"YYYY-MM-DD", channel, kind, accountId?, accountHandle?, status, publishAt?, reviewDeadline?, topicTitle?, pieceId?, origin:"auto"|"manual" }
```
- `coinsPerWeek` = Σ rule.count(주 환산) × (blog 1 + 채널 계약 기본 images.count) — 화면 «이 편성이면 주 N코인».
- `slots.roll`: 오늘~horizonDays 까지 규칙대로 slot(`planned`) 생성 · 멱등(같은 rule·date 중복 0) · quietDays 제외. **이번 라운드는 slot 생성까지**(소재 배정·D-3 제작·발행은 R2).

## 10. C 시나리오(라이브 = autocreate-endyd.netlify.app · 테스트 테넌트만)
1. 가입 → 운영센터 코인 지급 30 → 계정 2개(naver_blog·tistory) 연결 → 소재 새로 뽑기(검색량 숫자 존재) → 디렉터 제안(계정 배정·코인 합) → 확정(코인 차감 1회 · 재확정 시 재차감 0) → 생성 완료(in_review · 이미지 URL 200) → 게이트 리포트(AI티 0·고지 첫 블록) → 수정 저장 → 승인(scheduled) → 규칙 저장(주 3회) → 슬롯 생성(7일치·멱등) → 홈 todo/오늘 편성 반영.
2. 회귀: 로그인·로그아웃·운영센터.
3. 보안: 타 테넌트 id 로 pieces-get/accounts-remove → 404/403 · 자격 응답에 평문 0(`grep -i password` 응답 본문).
4. 증거: 라이브 URL·row id·스샷 경로 없이는 «실증»이라 쓰지 않는다.
