## 1. 🔴 먼저 실측 — 지금 무엇이 있고, 무엇이 거짓말을 하고 있나

설계를 쓰기 전에 코드를 읽었다. **넷이 나왔다.** 이 넷이 이 라운드의 뼈대다.

### 1.1 축은 **이미 있다**. 그런데 **아무도 안 부른다**

`lib/channel-registry.ts` 에 채널마다 `axis: "text" | "video"` 가 **이미 박혀 있다**. 16채널이 다 갈려 있다.

| 글 축(10) | 영상 축(6) |
|---|---|
| naver_blog · tistory · blogger · wordpress · threads · instagram · facebook · x · brunch · **naver_clip_post** | youtube_shorts · youtube_long · naver_clip · reels · facebook_reels · tiktok |

그리고 그걸 꺼내 주는 두 줄도 있다 — `TEXT_AXIS_KEYS` · `VIDEO_CHANNEL_KEYS`.

> 🔴 **부르는 곳이 0곳이다.** 서버도 화면도 안 쓴다. **정의는 있는데 제품이 안 부른다**(AC-69 — 어제 하루에 열다섯 번 나온 그것).

⇒ **R11 은 축을 «새로 만드는» 라운드가 아니다. 이미 있는 축을 «화면이 부르게 하는» 라운드다.** 이게 이 설계의 성격을 정한다 — 새 개념이 아니라 **배선**이다.

### 1.2 «종류»가 **셋**인데 만든 글 목록은 **둘**로 본다 — 그래서 **배지가 한 번도 안 붙는다**

`public/js/ui.js` 에 이미 이렇게 적혀 있다:

> «자리·글의 종류는 이제 **셋**이다(post·shorts·cardnews). 화면이 «영상이냐 아니냐»로만 갈라 보면 **카드뉴스가 글로 보인다**»

맞는 말이다. 그런데 **그 배지가 만든 글 목록에서는 안 붙는다.**

| 어디 | 넣는 값 | 배지표가 아는 값 | 결과 |
|---|---|---|---|
| **편성표**(`schedule.html`) | 슬롯 `kind` = `post`·`shorts`·`cardnews` | 같다 | ✅ 붙는다 |
| 🔴 **만든 글**(`pieces.html`) | piece `kind` = **`post`·`video`** | `shorts`·`cardnews` | ❌ **늘 빈칸** |

`UI.KIND_PILL = { shorts: "영상", cardnews: "카드뉴스" }` 인데 `pieces.html` 은 `UI.kindPill(p.kind)` 에 **`"video"`** 를 넣는다. 맞는 칸이 없어 **빈 문자열**이 나온다.

⇒ **만든 글 목록에서 영상도 카드뉴스도 이름표가 없다.** 채널 마크로 눈치채야 한다. 카드뉴스는 인스타 마크라 **피드 글과 구별이 안 된다.**

🔴 이건 R11 의 «있으면 좋은 것»이 아니라 **지금 틀린 것**이다. 축을 가르기 전에 **종류부터 바로 말해야** 한다.

### 1.3 같은 «kind» 라는 이름이 **넷**이다

| 이름 | 값 | 어디 | 무엇 |
|---|---|---|---|
| `pieces.kind` | `post` · `video` | DB·서버 | 만드는 길이 글이냐 영상이냐(3단계냐 6단계냐) |
| `RuleKind`(슬롯·규칙) | `post` · `shorts` · `cardnews` | `lib/slots.ts` | **주문의 종류**(«글 주 3회»와 «카드뉴스 주 3회»는 다른 주문 · 값도 다르다) |
| `FormatKey` | `story`…`cardnews`·`steps` | `lib/writing-contracts.ts` | 글의 **골격** |
| `channel.axis` | `text` · `video` | `lib/channel-registry.ts` | 채널이 **어느 축**인가 |

> 🔴 **다섯 번째 이름을 만들면 안 된다.** 어제 «흡수»·«→»로 옮겨 적은 항목을 옛 이름으로 세다가 숫자가 틀어졌다(AC-75).
> ⇒ R11 은 **`RuleKind`(post·shorts·cardnews)를 화면의 정본 어휘로 삼는다.** 이미 편성표가 쓰고 있고, 배지표가 이미 그 말을 한다. **새로 만드는 이름 = 0.**

### 1.4 🔴 만들기 화면이 **이미 정해 놓은 규칙 둘** — 축 설계는 이걸 어기면 안 된다

`create.html` 안에 주석으로 못 박혀 있다:

1. **«셋은 «모드»가 아니라 «입구»다»** — 미리 고르는 설정이 아니라 **그때그때 고르는 것**
   (사장님 «이것이 다 가능하게 하는 게 주요 골자»)
2. **«고른 칩은 화면 안에서만 산다(저장·URL 금지)»** — 새로 들어오면 늘 «전체».
   까닭도 적혀 있다: «**한 번 누르면 계속 그 상태**»가 사장님이 실제로 불편해하신 그것이다.

그리고 셋째, 같은 화면이 이미 이렇게 한다:

3. **채널이 하나면 칩을 아예 안 보여 준다.** 둘 이상일 때만 거를 것을 준다.

⇒ 🔴 **축도 이 셋을 그대로 따른다.** 아래 §2 의 결론이 여기서 나온다.

## 2. 그래서 축을 어떻게 가르나 — **탭이 아니라 «앞치마»**

### 2.1 안 하는 것 둘 — 왜 안 하는지 먼저 적는다

| 안 하는 것 | 왜 |
|---|---|
| ❌ **6번째 하단 탭**(«영상») | 헌장 §13.2 가 **탭 5개**로 고정돼 있다. 그리고 탭을 늘리면 «글만 쓰는 고객»이 **평생 안 쓸 탭**을 하나 이고 다닌다 |
| ❌ **전역 «글/영상» 스위치**(모드) | §1.4-1 «입구지 모드 아니다»를 정면으로 어긴다. 그리고 §1.4-2 «저장 금지»와도 싸운다 — 모드는 기억돼야 쓸모가 있는데, 기억하면 **어제 켜 둔 축에 오늘 갇힌다** |

> 🔴 그리고 실질적인 까닭이 하나 더 있다: **대부분의 고객은 축이 하나다.** 블로그만 하는 사람에게 «글/영상»을 고르게 하면 **없는 선택을 매번 시키는 것**이다.

### 2.2 하는 것 — **축은 화면마다 «입는 옷»이다**

> **하단 탭 5개는 그대로.** 축은 **세 화면에서만** 실제로 갈린다 — 그 셋이 사장님이 «다르다»고 하신 바로 그 셋이다.

| 화면 | 축을 어떻게 다루나 | 왜 |
|---|---|---|
| **만들기** | 🔴 **«배워 올 곳» 그룹을 새로 만든다** — 그 안에 **글 레퍼런스 · 영상 레퍼런스 두 줄**. 소재 목록은 **공유**(채널 칩이 이미 축을 가른다) | 사장님 «하위로 독립적으로»가 정확히 이것 · 소재는 §5 표에서 **공유**로 정해져 있다 |
| **만든 것** | **축 칩 한 줄**(전체 · 글 · 카드뉴스 · 영상) + 🔴 **배지 수리**(§1.2) | 여기가 «구별»이 제일 절실한 자리 — 지금 이름표가 아예 없다 |
| **수익** | 🔴 **«글에서 · 영상에서» 두 줄**을 매체 목록 **위에** · 못 가른 돈은 **«그 밖»으로 정직하게** | 사장님 «수익 내는 방식도 두 개가 기본적으로 다르잖아» |
| 검수 | **손 안 댄다** — 이미 갈려 있다(글은 읽고 고치기 · 영상은 보고 판단하기 · 단계도 3 대 6) | 이미 된 것을 다시 만들지 않는다 |
| 편성표 · 계정 · 소재 · 지갑 · 원장 | **공유** · 손 안 댄다 | 🔴 **사장님이 정하신 것** |
| 홈 | **손 안 댄다**(큰 숫자 하나 = 합계) | 헌장 «첫 화면 숫자 1개» |

### 2.3 🔴 축 칩의 규칙 — 만들기 화면의 선례를 **글자 그대로** 따른다

1. **축이 하나뿐인 고객에게는 칩이 아예 안 보인다.**
   (블로그만 연결한 사람은 «글/영상»을 평생 못 본다 — 그게 맞다)
2. **고른 값은 화면 안에서만 산다.** 저장 안 하고 URL 에도 안 남긴다. 다시 들어오면 늘 «전체».
3. **`.seg` 가 아니라 `.chips` 를 쓴다.** `.seg`(SegmentedTabs)는 이미 **열여덟 자리**에서 «화면 안 옵션»으로 쓰이고, `pieces.html` 에서는 **상태**(만드는 중·봐주세요·예약됨·발행됨)가 이미 차지했다.
   🔴 **같은 컨트롤이 한 화면에서 두 뜻을 가지면 안 된다.** 소재 화면이 **채널 칩**으로 똑같은 일을 하는 선례가 있다 — **같은 문제엔 같은 모양.**
4. 🔴 **새 컴포넌트 0.** 헌장의 12개 안에서 끝낸다(`.chips` · `.row` · `.pill` · `.group`).

## 3. 화면 하나씩

### 3.1 만들기 — «배워 올 곳» 그룹을 새로 만든다

**지금**: 레퍼런스가 «쓰는 길» 아래 **한 줄**로 있고, **쇼츠 전용**이다(«잘 된 쇼츠 링크 하나면… 하루 3개»).
**R10 이 끝나면** 글 레퍼런스가 새로 생긴다(캡처 + AI 비전). 그러면 **두 개가 성격이 다른 채로 나란히** 놓인다 — 그때 헷갈린다.

```
┌ 만들기 ─────────────────────────────────┐
│ 오늘은 어떻게 써 볼까요?                   │
│ 셋 중 아무거나 고르면 돼요                  │
│                                          │
│ 쓰는 길                                   │
│  ✦ AI에게 맡기기          소재만 고르면 …  › │
│  ✎ 내가 직접 쓰기         코인 0          › │
│  ⌸ AI가 쓴 걸 내가 고치기  봐주세요 2편    › │
│                                          │
│ 🔴 배워 올 곳          이번 달 3 / 10 남음  │   ← 새 그룹
│  ⧉ 글 스타일 배우기                       › │
│      블로그 주소를 넣으면 이모지·밑줄·       │
│      사진 배치까지 읽어 와요 · 코인 0        │
│  ▶ 영상 스타일 배우기                     › │
│      잘 된 쇼츠 링크 하나면 훅·서사를        │
│      배워요 · 코인 0                       │
│                                          │
│ 오늘의 소재 7                             │
│  [전체] [네이버 블로그] [쇼츠]             │   ← 이미 있는 채널 칩
│  …                                       │
└──────────────────────────────────────────┘
```

**규칙**

- 🔴 **글 축 계정이 없으면 «글 스타일 배우기»가 안 보인다.** 영상도 같다. (§2.3-1 과 같은 자)
- **한도는 그룹 제목 줄 우측에** — §13.0b 의 «그룹 섹션 «전체보기 ›»» 자리를 쓴다. 링크가 아니라 **글자**다(«이번 달 3 / 10 남음»).
  🔴 한도는 **요금제별**이고 **글·영상이 각각 센다**(성격이 다르다 — 글은 러너가 브라우저를 띄우고 비전을 부른다).
  ⚠️ 🔴 **«남음»을 지어내지 않는다** — 서버가 못 주면 숫자를 빼고 이름만 보여 준다(AC-9·AC-92).
- **두 줄의 말투를 맞춘다.** 지금 영상 쪽만 «하루 3개»라 되어 있는데, 글 쪽이 «이번 달 N개»면 **둘이 다른 말을 한다.** 🔴 **단위를 하나로 통일한다**(아래 §6 에서 사장님께 여쭌다).

> 🔴 **왜 그룹을 새로 만드나** — 지금처럼 «쓰는 길» 아래 줄로 붙이면 **레퍼런스가 «네 번째 쓰는 길»처럼 보인다.** 레퍼런스는 «쓰는 길»이 아니다 — **쓰기 전에 옷을 갈아입히는 일**이다. 그룹을 가르면 그 차이가 말 없이 전달된다.

### 3.2 만든 것 — 축 칩 + 🔴 배지 수리

**이름부터**: 지금 제목이 «만든 글»인데 **영상도 카드뉴스도 여기 있다.** 제목이 이미 거짓말이다.
⇒ **«만든 것»** 으로 바꾼다. (하단 탭 이름은 안 건드린다 — 이 화면은 홈 탭 밑이다)

```
┌ 만든 것 ────────────────────────────────┐
│ 만든 것                                   │
│ [만드는 중 2] [봐주세요 1] [예약됨 4] [발행됨] │  ← .seg (상태 · 그대로)
│ [전체] [글] [카드뉴스] [영상]               │  ← 🔴 .chips (종류 · 새로)
│                                          │
│ Ⓝ 에어프라이어 기름때 3분 청소             │
│    @cook_a · 내일 09:00          [예약됨] › │
│ Ⓘ [카드뉴스] 가을 옷장 정리 5가지           │   ← 🔴 지금은 이 배지가 안 붙는다
│    @life_c · 내일 12:00          [예약됨] › │
│ ▶ [영상] 3분 요리 · 60초                   │   ← 🔴 지금은 이 배지가 안 붙는다
│    @short_c · 내일 19:00         [예약됨] › │
└──────────────────────────────────────────┘
```

**고칠 것 (이게 §1.2 의 수리다)**

- 🔴 서버(`netlify/functions/pieces.ts`)가 목록 응답에 **`RuleKind` 한 칸**을 같이 실어 준다:
  `piece.kind === "video"` → `"shorts"` · `piece.format === "cardnews"` → `"cardnews"` · 나머지 → `"post"`
  ⚠️ **DB 값은 안 건드린다**(`pieces.kind` 는 그대로 `post|video`). **보여 줄 말**만 서버가 한 곳에서 정한다.
  🔴 **«가운데»를 여기서 정한다**(계약 §4-5) — 만드는 자리에서 «누가 읽나»를 정하고 **읽는 쪽(목록·칩·빈 상태)까지 같이** 넣는다.
- 화면은 그 칸을 `UI.kindPill()` 에 넣는다. **배지표는 안 고친다**(이미 맞는 말을 하고 있다).
- 🔴 **«post» 는 배지를 안 단다** — 기본이라 이름표가 붙으면 시끄럽다(ui.js 에 이미 그렇게 적혀 있다 · 그 결정을 유지한다).

**축 칩의 칸**

- 고객이 **가진 것만** 보여 준다. 카드뉴스를 한 번도 안 만들었으면 «카드뉴스» 칩이 없다.
- 칩을 누르면 **상태 세그와 곱해진다**(«봐주세요» × «영상»). 둘 다 비면 **빈 상태 한 문장**.
- 🔴 빈 상태 문장이 **종류를 안다**: «봐주실 **영상**이 없어요» (지금은 «봐주실 글이 없어요»라 영상 칩에서 틀린 말이 된다)

### 3.3 검수 — **손 안 댄다**

`piece.html` 은 이미 글/영상으로 갈려 있다(미리보기·단계·판정 축·손보기 시트가 전부 분기).
🔴 **이미 된 것을 다시 만들지 않는다.** R11 에서 이 화면에 손대는 것은 **R9 가 넣는 서식 미리보기**뿐이고, 그건 R9-7 이 이미 맡았다.

### 3.4 수익 — 🔴 **«글에서 · 영상에서»**, 그리고 **못 가른 돈은 숨기지 않는다**

사장님 말씀의 핵심이 여기다 — «수익 내는 방식도 두 개가 기본적으로 다르잖아».

**어떻게 가르나 — 🔴 «매체»로 가르지 않는다.**
매체로 가르면 **엑스**(글도 영상도) · **협찬** · **직접 입력**이 어느 쪽인지 영원히 모른다. 대신 **그 돈이 어디서 나왔는지**를 따라간다:

| 순서 | 재료 | 정확도 |
|---|---|---|
| ① | `revenue_daily.piece_id` → 그 글의 채널 → `axis` | **정확**(그 글에서 난 돈) |
| ② | 없으면 `revenue_daily.account_id` → 그 계정의 채널 → `axis` | **정확**(계정은 채널마다 한 줄이다) |
| ③ | 둘 다 없으면 | 🔴 **«그 밖»** — 못 갈랐다고 **적는다** |

> 🔴 ③을 한쪽에 몰면 안 된다. 그게 **폴백이 «모른다»를 «특정 값»으로 바꾸는 것**이다(AC-92). 돈 이야기에서 그 거짓말은 제일 비싸다.

```
┌ 수익 ──────────────────────────────────┐
│  ‹  2026년 9월  ›                        │
│                                          │
│  9월에                                   │
│  284,100원 벌었어요                       │   ← 큰 숫자는 하나(합계) · 그대로
│  지난달 같은 날까지보다 67,300원 더         │
│                                          │
│  어디서 났나                              │   ← 🔴 새 그룹
│   글에서      ▇▇▇▇▇▇▇  198,400원         │
│   영상에서    ▇▇▇        71,200원         │
│   그 밖        ▇          14,500원  ⓘ     │   ← 🔴 «어느 쪽인지 못 갈랐어요»
│                                          │
│  매체별                                   │   ← 지금 있는 목록 그대로
│   A 애드센스   ▇▇▇▇▇  121,000원          │
│   쿠 쿠팡      ▇▇▇      88,400원          │
│   …                                      │
└──────────────────────────────────────────┘
```

**규칙**

- 🔴 **막대는 단색 + 1등만 잉크**(헌장 «다색 차트 금지»). 글/영상을 **다른 색으로 칠하지 않는다** — 축이 색이 되면 화면의 «색 3개»가 깨진다.
- «그 밖»이 **0원이면 줄 자체를 안 그린다.** 0을 보여 주면 «뭔가 잘못됐나» 싶다.
- «그 밖» 옆 ⓘ 를 누르면 바텀시트 한 문장: «**계정이나 글에 연결되지 않은 수입이에요 — 협찬·직접 입력처럼요.**» 🔴 겁주지 않는다(§3).
- 🔴 **축이 하나뿐인 고객에게는 «어디서 났나» 그룹이 통째로 안 나온다.** 블로그만 하는 사람에게 «영상에서 0원»은 소음이다.
- 🔴 **큰 숫자는 여전히 하나다.** 축별 숫자를 위로 올리지 않는다(헌장 «첫 화면 숫자 1개»).

### 3.5 편성표 · 계정 · 소재 · 지갑 · 원장 — **공유 · 손 안 댄다**

🔴 사장님이 정하신 것이다. 그리고 까닭이 코드에도 있다(R9 §5.1):

- **인스타 계정 하나가 피드도 릴스도** 한다 · **네이버 ID 하나가 블로그도 클립도** 한다.
- 나누면 **하루 상한·간격을 양쪽이 따로 센다** → 오전 10시 글, **10시 5분 릴스**가 같은 계정에서 나간다.
- 사장님이 세우신 **«계정 하나 = IP 하나»**가 화면에서 깨진다.

⚠️ 다만 편성표는 **이미** 종류 배지를 제대로 달고 있다(§1.2 표) — **그대로 둔다.**

### 3.6 홈 — 손 안 댄다

큰 숫자 하나(오늘 번 돈) · 해야 할 일 · 오늘 편성. **축을 홈에 올리지 않는다** — 홈은 «오늘 무슨 일이 있나»이지 «어느 공장이 돌았나»가 아니다.

## 4. Orbit 다섯 — 화면으로

> R9 §6 에서 «데이터는 이미 있다»고 적었다. **코드에서 확인했다** — `lib/cron/learn.ts`(6·24·72시간 성과 회수) · `lib/publish-gap.ts` · `lib/slots.ts` · `contract.reader` 가 다 있다.
> ⇒ 다섯 다 **«만드는 일»이 아니라 «화면이 부르게 하는 일»**이다. §1.1 과 같은 성격이다.

### 4.1 채널 추세 — «오름 · 멈춤 · 내림» + **언제부터**

- **어디**: 수익 화면의 매체별 줄 우측에 작은 글자 한 칸 (새 화면 0)
- 최근 7일 ↔ 직전 7일. 🔴 **3편 미만이면 판정하지 않고 «아직 몰라요»**(AC-9 — 지어내지 않는다)
- 🔴 **«내림»을 빨강으로 칠하지 않는다.** 수익 화면은 감소도 **잉크 중립**이다(§13.0b 에 이미 그렇게 적혀 있다)

### 4.2 성과 저하 알림 — **되먹임 원장의 첫 실사용**

- 7일 평균보다 **15% 낮으면** 홈 «해야 할 일»에 한 줄
- 🔴 **겁주지 않는 문장으로**(§3). 금지: «수익이 떨어지고 있습니다» / 한다:
  > «지난주보다 조회가 줄었어요 — **이 소재군이 잘 먹혔어요: 에어프라이어·주방 정리**»
  ①사실 한 줄 ②어떻게 하면 되는지 ③우리가 대신 해 주는 것
- 아이콘은 `UI.KIND.gauge`(이미 있다) — 🔴 **새 아이콘 안 만든다**(ui.js 495줄 규칙)

### 4.3 «이날 겹쳐요» — 🔴 **막지 않기로 했으니 «보여 주기»가 더 세져야 한다**

- 계산은 `lib/publish-gap.ts`·`lib/slots.ts` 에 **이미 있고 화면이 없다**
- **어디**: 편성표에서 날짜를 누른 시트 · 예약 시각을 고르는 자리 **둘 다**
- 문장: «이날 @cook_a 에 이미 2편 있어요 · **30분 안에 붙어요**» + **«그래도 이 시각»** 단추
- 🔴 **막지 않는다**(§9 하드 게이트 0). 되돌릴 길(시각 바꾸기)을 **같이** 준다

### 4.4 계정마다 독자 — 계약의 `reader` 를 **계정이 덮어쓴다**

- 지금 독자는 **채널 계약에 고정**(`contract.reader` — «내 블로그 이웃», «검색으로 들어온 사람»)
- 같은 네이버라도 «살림 검증»과 «작은 돈 재테크»는 독자가 다르다
- **어디**: 계정 상세 시트에 칸 하나. 비우면 **계약 값 그대로**(지금과 같다)
- 🔴 **허용 목록을 같이 넓힌다** — 어제 **세 곳**에서 저장은 200 인데 새로고침하면 사라졌다(`ALLOWED_SETTINGS`·`sanitizeProfile`·`pieces-get meta`). **이 칸이 네 번째가 되면 안 된다.**

### 4.5 글도 제작 단계 — 영상엔 있고 글엔 없다 … **가 아니었다**

- 영상은 `UI.VSTAGE_SAY` 6단계(대본→목소리→장면→합성→검사→완료)
- ⚠️ 🔴 **코드를 읽으니 글 쪽도 이미 3단계가 있다** — «글 쓰는 중 → 사진 만드는 중 → 검사 중»(`pieces.html` `stepBar`).
  ⇒ R9 §6-5 가 «글은 «만드는 중»뿐»이라고 적은 것은 **틀렸다.**
  ⇒ R11 의 몫은 **«그 3단계를 검수·홈에서도 같은 말로 쓰나»** 를 맞추는 것뿐이다. **작게 줄어든다.**
  🔴 **줄어든 것을 조용히 넘기지 않고 여기 적는다**(축소가 아니라 **이미 되어 있었다**).

## 9. 이 설계가 스스로 지킬 것

1. 🔴 **«정의가 있나»가 아니라 «제품이 부르나»**(AC-69) — R11-10 이 이 라운드의 **양심**이다. `axis` 를 또 «정의만 하고 안 부르는» 상태로 두면 이 설계는 실패다.
2. 🔴 **검사는 일부러 망가뜨려 봐야 믿는다** — 배지 수리는 **«카드뉴스인데 배지가 없으면 빨개지는»** 검사가 있어야 끝난 것이다.
3. 🔴 **«가운데»를 먼저 정한다** — `RuleKind` 한 칸을 서버가 만들 때 **읽는 쪽(목록·칩·빈 상태)까지 같이** 넣는다.
4. 🔴 **못 가른 것은 «못 갈랐다»고 적는다** — 수익 «그 밖»이 이 설계의 정직함이 걸린 자리다.
5. **줄어든 것도 적는다** — §4.5 는 코드를 읽으니 **이미 되어 있었다.** 조용히 넘기지 않았다.
