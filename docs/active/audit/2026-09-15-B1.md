## A. 특별 항목 — 영상 축이 고객 화면에서 실제로 쓰이는가

**라이브 실측(읽기 SELECT · 2026-09-15)**


**고객 경로를 따라간 결과**
1. **계정 연결 그리드** — `public/app/accounts.html:38` `.filter((c) => !c.status || c.status === "active" || cnt[c.key])` = «가동 전(planned) 채널은 숨긴다». 레지스트리가 영상 4채널 전부 `planned` 라 **고객은 영상 채널을 볼 수도 연결할 수도 없다.** 운영센터 `public/ops/channels.html:48` 상태 세그먼트로 `active` 로 바꿀 수 있고 힌트도 «가동이면 고객이 바로 연결할 수 있어요»인데 **한 번도 켜지지 않았다.** → 이것이 «영상이 전부 빠져 있다»의 직접 원인(코드가 없어서가 아니라 **문이 잠겨 있어서**).
2. **디렉터** — `director.ts:154-157` `wantVideo = kinds.includes("video")` **그리고** 살아 있는 영상 계정이 있어야 영상 piece 를 낸다. 1 때문에 계정이 0 → 영상 제안 0 → `pieces kind='video'` 0.
3. **kinds 스위치** — `public/onboarding.html:49` 는 기본 `["text","video"]` 로 저장하고 영상 채널이 안 열렸으면 «곧 열려요» 칩(정직). 그러나 **온보딩 뒤에 켜고 끄는 화면이 없다**(settings.html 의 kinds 칩은 내보내기용). 기존 테넌트 87/99 는 영상이 꺼진 채로 있고 켤 길이 없다 → 🟡.
4. **유튜브 OAuth 없이 «만들기 → 심사 → 내려받기 → 직접 올리기»** — 코드상 열려 있다: `youtube_shorts` 는 OAuth 앱 키(`GOOGLE_OAUTH_CLIENT_ID`) 없으면 `provider_not_configured` → 계정 연결에서 «준비 중이에요»(accounts.html:74) 🔒. **`naver_clip` 은 `connectMethod:"session"`** 이라 OAuth 없이 계정을 붙일 수 있고(accounts.ts:133 · 네이버 블로그와 같은 세션) → 디렉터가 클립 30초 영상을 내고 → `piece.html` 에서 `<video controls>` 재생 + **SRT 내려받기**(`:56`) → 발행은 러너 스텁 `runner/channels/naver-clip.mjs`(`not_supported_yet`) → `awaiting_manual` + 알림 «클립은 앱에서 올려 주세요» → `posts.html:17` «직접 올리기» 탭. **이 경로가 OAuth 없는 실경로다.** 그런데 naver_clip 도 1 에서 숨겨져 있어 시작조차 못 한다.
5. **내려받기의 마지막 조각** — `piece.html` 에 **mp4 «영상 내려받기» 버튼이 없다**(`download=` 는 SRT 뿐). 데스크톱 크롬은 플레이어 컨트롤로 받을 수 있지만 **모바일 사파리는 못 받는다** — «직접 올리기»는 폰에서 하는 일이다 → 🟠.
6. **직접 올린 뒤 주소를 적을 곳이 없다** — `posts.html:77` «직접 올리기» 시트는 «본문 복사하기»뿐이고 `posts.ts` 에 URL 을 적는 API 가 없다 → piece 가 영원히 `awaiting_manual` 이고 수익 매칭(piece↔URL)도 안 된다(B3 지적 · §4.2 행 추가) → ❌.
7. **레지스트리 `active` 로 켜면 무엇이 열리나**(코드 판정 · 실측 아님): naver_clip 연결 → 30초 영상 제작 → 검수 → SRT 받고 플레이어로 저장 → 앱에서 직접 올리기. youtube_shorts 는 OAuth 키·앱 심사(R5 §7 사장님 액션) 뒤 비공개 업로드까지. reels 는 Meta 앱 키 뒤.

**결론 한 문단**: 영상 축은 R5 계약 §1 기준 **코드 100% · 화면 8장 존재 · 라이브 렌더·BGM 믹스 실측까지 끝난** 상태다. 그러나 고객 경로의 **첫 문(계정 연결 그리드)** 이 `channel_registry.planned` 로 잠겨 있고 그 문을 여는 손잡이는 운영센터에만 있다. 사장님이 «영상 관련이 전부 빠져 있다»고 보신 것은 정확한 관찰이며, 원인은 **누락이 아니라 미개통**이다 — 운영센터에서 `naver_clip`(과 원하면 `youtube_shorts`)을 `active` 로 바꾸는 순간 OAuth 없는 경로가 그대로 열린다. 그 뒤에 남는 실제 결함은 4개: **mp4 내려받기 버튼 없음(🟠 · S)** · **직접 올린 주소 적기 없음(❌ · S · B3 지적)** · **온보딩 뒤 영상 켜기 화면 없음(🟡 · S)** · **프레임 지문 미작동(🟠 · L)**. 즉 «앱에서 직접 올리기» 경로는 문을 열어도 **뒤 두 칸(받기·적기)이 막혀 있다.**
