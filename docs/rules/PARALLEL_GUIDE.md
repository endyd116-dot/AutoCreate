# PARALLEL_GUIDE.md — 4채팅 병렬 작업 규칙 (AutoCreate)

> AM(AutoMarketing) PARALLEL_GUIDE 이식(2026-09-14). MIS→AM에서 검증된 모델. 새 라운드 시작 시 메인 정독. A·B·C는 시작 시 본 문서 + `CLAUDE.md` + `docs/rules/PITFALLS.md` 상단 + 설계서 본인 § 정독.

## 1. 역할·영역

| 채팅 | 모델 | 역할 | 변경 영역 | 금지 영역 |
|---|---|---|---|---|
| **메인** | Opus | 설계·머지·조율·**push 단독** | `docs/active/`, `PROJECT_STATE.md`, 머지 커밋 | 코드 직접 구현(설계만·사소한 즉답 fix 예외) |
| **A** | Sonnet | 프론트 | `public/**`, `assets/**` | `lib/`, `netlify/`, `db/`, `drizzle/`, `runner/` |
| **B** | Sonnet | 백 | `netlify/functions/`, `lib/`, `db/schema.ts`, `drizzle/`, `runner/`, `scripts/`, `package.json`, `.env.example` | `public/`, `assets/` |
| **C** | Opus | 검증·fix·백필 | 전 영역(fix·검증보고 한정) | 신규 기능 추가 |

> A·B 둘 다 `PROJECT_STATE.md`·`docs/` **수정 금지**(머지 충돌). 상태는 메인에 보고 텍스트로만.
> 러너(`runner/`)는 B 영역이다. 러너 «화면»(트레이 앱 UI)이 생기면 그때 A/B 경계를 트리거에 명시.

## 2. 머지 순서 (강제)
```
B 백 머지 → DDL 적용(scripts/neon-migrate.mjs) + schema.ts 갱신 확인
 → A 프론트 머지 → C 검증 → C fix(있으면) 머지 → 메인 라운드 마감
```
- 어기면: A 먼저=호출할 백 없음 / DDL 전 schema 활성화=drizzle SELECT 깨짐.
- **B 머지 전**: B 응답 키 ↔ A mock 키 1:1 일치 확인.

## 2.5 🔴 A·B 동시 발사
**A와 B는 같은 라운드에서 «동시에» 발사한다.** 순차는 한쪽이 노는 시간이 낭비다. 이름 충돌은 순서가 아니라 **계약**으로 막는다:
1. 키 이름을 **실제 글자로** 적는다 — «A가 정한다»·«적절히»는 계약이 아니다.
2. 🔴 그 이름이 라이브에 이미 쓰이는지 **`grep`으로 먼저 확인**한다.
3. GET 투영 키와 body 키를 **양쪽 다** 적는다(이름·모양·«없으면 키를 안 싣는다»까지).
4. A·B 트리거의 계약 코드블록은 **정본과 바이트 일치**.
> 어긋나면 메인이 머지에서 봉합(관례: A 이름 정본·B 이름 폴백).

## 2.6 🔴 라운드 파이프라이닝 (사장님 지시 2026-09-14 — 기본 운영 방식)
**C 가 라운드 N 을 검증하는 동안 메인은 라운드 N+1 을 설계하고 A·B(·B2)를 먼저 발사한다.** 라운드를 직렬로 붙이면 검증 시간만큼 A·B 가 논다.
- **C 가 찾은 결함은 C 가 직접 고친다**(P0·P1 모두 · `fix/<round>-*` 브랜치). A·B 에 되돌리지 않는다 — 그들은 이미 다음 라운드에 있다.
  예외: 화면 한 장을 다시 짜야 하는 큰 수리는 결함이 아니라 **다음 라운드 항목**으로 올린다(메인 판단).
- **베이스**: N+1 브랜치는 «N 머지된 main»에서 딴다. C 의 fix 가 main 에 들어오면 메인이 알리고 각 워크트리가 `git merge main`.
- **파일 겹침 최소화**가 조건이다 — 메인은 N+1 트리거를 쓸 때 «C 가 지금 만지는 파일»과 겹치는 항목을 뒤로 미루거나 담당을 갈라 적는다.
- 배포 순서: N 배포(라이브) → C 라이브 검증 → C fix 배포는 N+1 배치에 묻어 간다(배포 횟수 유지).

## 2.7 🔴 일하는 방식 (2026-09-16 확정 · AC · AM 공통 정본)

> 사장님: «메시지 소통으로만 하니 **사소한 개발 하나가 너무 오래 걸린다.**»
> AC 가 하루를 되짚어 재고, AM 이 자기 실측을 더해 **양쪽 공통 정본**으로 합친 것이다.
> 한 줄: 🔴 **«이어졌나»를 나중에 찾지 말고 만드는 순간에 박는다. 그리고 검사는 일부러 망가뜨려 봐야 믿는다.**

### AC 실측 — 시간은 «만드는 데»가 아니라 «만든 게 안 이어진 걸 나중에 찾는 데» 샜다
2026-09-16 하루(커밋 75 · 머지 22 · 창 6): «만들어 놓고 아무도 안 부른다» **15건** · «검사가 틀려서 미개발로 셈» **6건** · 창 잘못 짚음 **4건**.
⇒ **21건이 «만든 게 안 닿아서»** 생겼고, 그걸 찾는 시간이 만드는 시간보다 길었다.

### 다섯 (AC)
1. 🔴 **만들 때 «양끝»이 아니라 «가운데»를 먼저 정한다.** 새 값을 만들면 그 자리에서 «누가 읽나»를 정하고 **읽는 쪽 코드까지 같이** 넣는다. 못 넣으면 «아직 화면 없음»이라고 **적는다**. 검사 한 줄도 같이 박는다 — «정의가 있나»가 아니라 **«제품이 부르나»**(AC-69).
2. 🔴 **검사는 일부러 망가뜨려 봐야 믿는다(음성 대조).** «이 방어를 빼면 빨개지나»를 한 번 돌린다. **빨강이 안 나오면 그 검사는 아무것도 못 잡는다**(AC-87).
3. **만든 사람이 자기 걸 검증하지 않는다.**
4. 🔴 **발부는 문서로, 보고는 메시지로** — 경계는 아래 표.
5. **사람(사장님) 손이 필요한 건 한 문서에 모으고 기다리며 멈춰 서지 않는다.**

### 넷 (AM 실측 — AC 목록에 없던 시간 도둑)
① 🔴 **검증은 층을 나눈다 — 무거운 검사 ≠ 정확한 검사.**
  AM 은 변수 하나 옮긴 커밋에 관문 7개(30분)+재촬영(15분)+눈검수 156장(30분)을 붙였는데 **표본 8장에 긴 제목이 없어 회귀를 놓쳤다.**
  ⇒ **매 커밋** = 초 단위 계산값 표 + 부류별 «빨개질 표본» 1장(음성 대조) · **촬영 관문** = 최종 해시에만 · **눈검수** = 바뀐 그림만(픽셀 대조로 거른 뒤).
② 🔴 **C 는 B 의 모든 커밋을 «다른 모양의 자»로 잰다.** 같은 하니스 재실행은 검증이 아니다.
  ⇒ **창을 늘리지 말고 이 역할을 C 에 고정한다.**(AC 도 같은 날 이걸로 6건을 뒤집었다)
③ 🔴 **메인은 직렬 병목이 되지 않는다.** 기술 질문은 **창끼리 직접**(B↔C · A↔B) · 메인은 **범위·머지·사장님 결재**만.
  🔴 **메인이 글 쓰는 시간이 곧 사장님 대기 시간이다.**(2026-09-16 AC 메인이 정확히 이걸로 느렸다)
④ **머지를 미루지 않는다.** 검증 끝난 브랜치는 **즉시 로컬 main 에**(비용 0) · 미루는 것은 **push(배포) 하나뿐**. 미루면 동료가 main 끝에 두 번 세 번 다시 맞춘다.

### 🔴 문서↔메시지 경계 (AM 이 손본 자리 — AC 판이 너무 절대적이었다)
| | 쓰임 |
|---|---|
| **문서(트리거)** | **협업이 필요한 일** — 둘 이상 창이 맞물림 · 되돌리기 필요 · 사장님 결재 포함. **라운드 시작은 트리거 한 방**(네 창 몫을 한 문서에 · 🔴 **담당 표 포함**) |
| **메시지 5줄** | **협업이 필요 없는 일** — 단일 창 · ~30분 · 계약 없음. **30분짜리에 문서를 만들면 늦다**(AM 오늘 가장 빨랐던 일이 5줄 발부 → 35분 만에 수리+검산) |
| **보고** | 메시지 **10줄 이내** · 상세는 상태 파일. 🔴 2026-09-16 메시지가 넘친 건 발부가 아니라 **«긴 보고»**였다 |

### 창 개수 — **4개 고정**
`A` · `B` · `B-2` · `C`(검증) + 메인. 일이 많으면 **창을 늘리지 말고 라운드를 쪼갠다.**
근거: 창 4개면 붙일 짝이 6개인데 **6개면 15개**다. 2026-09-16 AC 사고 4건이 **전부 창을 늘린 뒤** 났다.

### 메시지가 **진짜로 버는 것 둘** — 이건 버리지 마라
1. **세션이 세션에게 직접 넘기기** — 한 창이 자기 작업을 버리면서 «내 쪽에만 있던 둘»을 넘겼고, 그 둘이 **되돌릴 수 없는 사고**(같은 글 두 번 발행)를 막았다.
2. **«멈춰라»가 즉시 가는 것** — 새 창이 남의 폴더에 들어가기 **직전에** 세웠다. 문서로는 그 속도가 안 난다.
⇒ 답은 «메시지를 없애라»가 아니라 **«메시지로 발부하지 마라»**다.

## 2.8 🔴 트리거는 **사장님께 드린다** — 메인이 창에 직접 쏘지 않는다 (사장님 지시 2026-09-19)

> «다음부터는 트리거를 나한테 줘. 그럼 내가 A,B 한테 직접 보낼게. 세션 차면 A,B 계속 새로 만드는데, **너가 가끔 새로운 A,B를 모르더라고.** 내가 그들한테 복붙하는 게 빠를 듯해.»

🔴 **이유는 실사고다(2026-09-19).** `ListAgents` 에 AutoCreate 창이 **열 개**였고 메인이 **이름으로** B 를 짚었는데 틀렸다 — `autocreate-b-4e` 가 아니라 `autocreate-b-1d` 였다. 게다가 **둘이 같은 폴더**(`../AutoCreate-B` · `feature/r11-back` · HEAD 같음)였다. 🔴 **가드가 없었으면 두 창이 한 워크트리를 동시에 만져 서로를 덮어썼다.**

🔴 **이름은 재시작마다 바뀌고 메인은 못 따라간다. 폴더가 정체다. 그리고 창을 보고 계신 것은 사장님이다.**

- 트리거를 만들면 ① `docs/active/...-trigger.md` 에 커밋하고 ② **같은 내용을 답변 안에 «복붙 가능한 한 덩어리»로** 낸다.
  🔴 **파일 경로만 주는 것은 «보낸 것»이 아니다** — 그 창은 파일이 생긴 줄도 모른다(2026-09-19 메인이 «트리거 나감»이라고 틀리게 보고했다).
- 🔴 **«트리거 나갔다»고 말하지 마라.** 사장님이 붙여 넣으셔야 간 것이다. 보고 어휘 규칙(§5.5)과 같은 종류다.
- 예외: **이미 폴더·브랜치를 그 창이 직접 답해 신원이 확인된 창**에 이어서 한 줄 묻거나 «멈춰라»를 보내는 것은 괜찮다. 사장님 손이 필요한 것은 — **새 몫을 배정하는 첫 발사**다.
- 창이 스스로를 못 가릴 때 쓰는 가름: **폴더·브랜치·HEAD 를 한 줄로 답하게 한다.** 창 이름은 자기가 못 본다.

## 3. 워크트리 (필수)
```
AutoCreate          메인   main
../AutoCreate-A     A      feature/<round>-front
../AutoCreate-B     B      feature/<round>-back
../AutoCreate-C     C      verify/<round> | fix/<이름>
```
- 셋업: `git worktree add ../AutoCreate-A -b feature/<round>-front main` (최초 1회) · 이후 `cd ../AutoCreate-A; git checkout -B feature/... main`.
- 베이스 = **로컬 `main` HEAD**(설계 포함). 워크트리 공유라 origin push 불필요.
- A·B·C 워크트리는 `node_modules`를 각자 설치(`npm ci`).

## 4. 자율주행 정책 (전원)
모든 트리거 상단에 이 블록을 그대로 넣는다:
```
[자율주행 — 완전 자율]
- 파일 R/W/Edit, git(add·commit·checkout·merge·rebase·fetch·restore·worktree), bash·PowerShell, npm install/run, npx, curl(검증) — 전부 묻지 말고 자율 실행. 도구 허락 구하지 말 것.
- 커밋 자유. push 불필요 — 메인이 공유 git에서 너의 로컬 브랜치를 직접 머지·배포함. 끝나면 [브랜치·커밋해시·변경요약]만 보고. "push 막혔다/직접 해달라" ❌ (정상이니 그냥 보고).
- 오직 ①진짜 애매한 로직·기능 해석 ②중요한 워크플로우/아키텍처 결정 ③비가역 위험작업(force push·reset --hard·DB drop)일 때만 멈추고 질문.
- 막히면 30분 안에 보고.
[진행률 보고 — ★의무] 시작 0%부터 섹션 착수·완료마다 "📊 진행률 X%/100 — 방금: … / 다음: …" 한 줄을 텍스트로. 최소 4~5회. 완료 시 100% 한 번만 찍는 것은 위반. % 값은 트리거 섹션 제목의 % 지도에서 읽는다(계산 금지).
```
> ★ **% 지도 의무**: 메인은 트리거의 각 섹션 제목에 % 구간을 직접 배정한다(`## B1 (0→25%)`). % 지도 없는 트리거 = 메인의 작성 미준수.
> push/배포: `main` push(=실배포)는 메인 단독. A·B·C settings는 routine 도구 allow + `main` push deny.
