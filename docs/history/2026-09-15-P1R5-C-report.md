## 2. 결함 ② + 수리 — 심사가 «계획서»가 아니라 «산출물»을 본다 (`ac147de`)

메인이 «러너 보고를 믿는 심사 축이 또 있는지 훑어라» 해서 찾은 것. **AC-31(13초 꼬리)이 심사를 통과한 이유**다.

```
전:  러너 → durationMs = (-t 에 넘긴 bodySec)        frameCount = durationMs/1000 × fps
     심사 → |frames − dur×fps| ≤ 45   ← 같은 식에서 나온 두 값을 견주니 **정의상 항상 참**
            frameCount < 10           ← 영영 안 걸린다
     ⇒ 컨테이너 15s / 영상 12s 인 파일도 «길이 규격 안» 으로 통과
후:  러너 → ffprobe 로 containerMs·videoMs·audioMs·실프레임을 **재서** 보고(measured:true)
     심사 → 컨테이너 − 영상 > 0.5s 면 duration_fit **P0 차단** · 프레임은 실측일 때만 판정
            실측이 없으면(옛 러너·ffprobe 없음) **판정 보류**(통과도 실패도 아님 · AC-9)
```
| 파일 | 한 일 |
|---|---|
| `runner/channels/render-video.mjs` | `resolveFfprobe()` 사다리(env `FFPROBE_PATH` > ffmpeg 옆자리 치환 > PATH > winget shim) · `measureOutput()` · `caps.ffprobe` |
| `lib/video/types.ts` | `RenderReport += containerMs·videoMs·audioMs·plannedMs·measured`(전부 선택 = 옛 러너 호환) |
| `lib/video/judge.ts` | `TAIL_TOLERANCE_MS=500` · 실측 기반 `duration_fit`·`frames_not_blank` · 🔴 **8KB 헤더 가드 유지 · 150KB 류 문턱 금지**(B-1 경고 반영) |
| `lib/video/render-queue.ts`(B2 파일 · 1곳) | 실측 필드를 `piece_assets(video).meta` 에 보존 — 여기서 흘리면 `judgeVideo` 가 다시 계획값을 본다 |

**음성 대조(«검사가 진짜 잡는가»)**
| 보고 | 기대 | 결과 |
|---|---|---|
| 컨테이너 15.00s · 영상 12.00s(꼬리 3.00s · B-1 되돌린 빌드 참값) | 실패 | ✅ `next failed` · `duration_fit` 실패 «컨테이너 15.00s 가 영상 12.00s 보다 3.00s 길어요 — 끝에 정지 화면이 붙어 있어요» |
| 컨테이너 = 영상 12.00s | 통과 | ✅ `in_review` |
| 실측 필드 없음(옛 러너) | 죽지 않고 보류 | ✅ 통과 + 사유 «러너가 잰 값이 아니라 계획값 — 꼬리 판정 보류» |

### 8.2 라이브 렌더 실증 — 2초(사장님 지시 «2초짜리 테스트영상만» · 원가 0)
60초/$6.4 대신 **provider 클립 0 · TTS 0**(장면 = PNG 2장)으로 2초를 구웠다. 목표였던 «`measured` 가 러너→서버→DB 까지 흐르는가»는 그대로 재고, **거기서 결함이 나왔다.**
