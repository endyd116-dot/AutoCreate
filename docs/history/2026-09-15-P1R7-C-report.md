## 2. 이번에 찾은 결함 — 1건(고객 차단)

### 🔴 제휴 링크를 **한 개당 두 번** 세고 있었다 — «2개 이하» 가 실제로는 «1개 이하»

* **증상**: `renderBlocksHtml` 로 만든 **쿠팡 상품 2개짜리 정상 글** → `countAffiliateLinks` 가 **4** → `runPublishGate` `ok=false`(떨어진 검사 `affiliate_count`) → 발행 직전에 막혀 `awaiting_manual` → 고객에게 «직접 올려 주세요».
* **원인**: 두 조건을 **따로 더했다**(`class="affiliate"` 수 **+** 쿠팡 도메인 href 수). 그런데 `lib/blocks.ts:74` 의 렌더러는 `<a class="affiliate" href="https://link.coupang.com/…">` 로 **둘 다** 내놓는다. 손으로 붙인 직링크까지 세려던 의도는 맞는데, **셈의 단위가 «조건» 이지 «링크» 가 아니었다.**
* **범위**: 같은 셈이 `lib/content-approve.ts:103` 에 **한 벌 더** 있었고 똑같이 두 번 셌다(AC-29). 검수창의 «제휴 링크 N개» 와 발행 직전 판정이 **갈라져 있었다.**
* **수리**: `<a>` 태그를 훑어 **둘 중 하나라도 해당하면 1개**로 센다. 두 벌을 한 함수로 합쳤다.
* **실측(수리 뒤)**: 상품 2개 → 2 · `ok=true` **통과** ｜ 상품 3개 → 3 · `ok=false` **여전히 막는다**(양성 대조가 게이트를 무력화하지 않았다) ｜ 렌더 1 + 손으로 붙인 직링크 1 → 2(의도했던 동작 보존). `tsc --noEmit` 통과.
* **브랜치**: `fix/r7-affiliate-count` · `2ac1aa1` (main 에서 딴 것 · B2 파일 겹침은 §5 에 적었다)

> 이 결함이 왜 여태 안 보였나: 지금까지의 검사가 전부 **문자열로 흉내 낸 본문**을 먹였기 때문이다. 흉내로 재면 «3개는 막힌다» 만 보이고 통과한다.
> **진짜 렌더러가 내놓는 본문**으로 재자마자 나왔다(AC-31 «심사는 계획이 아니라 산출물을 재라»의 재확인).

### 5.1 🔴 «내 catch 가 내 눈을 가렸다» (#7 · 이 라운드의 공유 교훈)

파기 절의 씨앗 INSERT 에 `.catch(() => {})`, 검증 조회에 `.catch(() => [])` 를 달아 뒀다.
씨앗은 **컬럼 불일치로 0행**이 들어갔고, 조회는 **없는 컬럼(`meta`)으로 던졌다.** 둘 다 조용히 삼켜졌고, 합쳐져서 **«영수증까지 전부 삭제 — 전자상거래법 위반 소지»** 라는 **가짜 P0** 로 읽혔다.
수리 뒤 실측: **영수증 1행 보존 · `tax_biz`·`detail` 식별자 0건.** 제품은 처음부터 맞았다.
→ **AC-36 의 사촌이다.** `void` 가 서버의 부작용을 지우듯, `.catch(()=>{})` 는 **하니스의 증거**를 지운다.

### 5.2 🔴 «틀린 초록을 잡는 하니스가 스스로 틀린 초록을 만들었다» (#9 · AC-55)

⑤의 음성 대조 3건(제목 없는 200 · 404 · 제목 미첨부)이 **전부 초록**이었다 — `stats` 가 비어 있었으니까.
그런데 `stats` 가 빈 이유는 제품이 도장을 **안 찍어서**가 아니라 **내 보고가 아예 처리되지 않아서**였다(`not_claimed(running)`).
**처리되지 않은 보고는 «도장이 없다» 의 증거가 될 수 없다.**
→ 모든 절에 `took()` 선행 조건(보고가 `done` 으로 **처리됐는가**)을 박았다. 그러자 음성 대조가 **진짜**가 됐다:
`stats 키 [alive,views,lastSyncAt]` — **병합 가지는 돌았고 `public` 만 뺐다.** 이것이 내가 원래 갖고 싶었던 증거다.

## 7. PITFALLS 에 올릴 것

* **AC-56(제안)** — **하니스의 `.catch(() => …)` 는 증거 인멸이다.** 씨앗·검증 조회의 예외를 삼키면 «제품이 지웠다» 와 «내가 못 넣었다» 가 같은 모양으로 보인다. 검사 코드의 catch 는 **반드시 출력한다.**
* **AC-57(제안)** — **음성 대조는 «아무 일도 안 일어났다» 로 증명되지 않는다.** «그 경로가 **실제로 돌았고** 그 항목만 빠졌다» 까지 봐야 한다. 선행 조건(처리됐는가)을 먼저 못 박아라.
* **AC-58(제안)** — **하니스 출력을 `| head` 로 자르지 마라.** SIGPIPE 로 프로세스가 죽으면 `finally` 의 teardown 이 안 돈다. 전부 받고 나중에 골라 읽어라.
